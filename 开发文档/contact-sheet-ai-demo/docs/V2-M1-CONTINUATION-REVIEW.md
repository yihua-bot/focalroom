# v2 M1 接续开发评审

处理结果：R1–R3 已在 [修复报告](V2-M1-REVIEW-FIXES-TEST-REPORT.md) / ADR 0028 中关闭，下文保留修复前的评审与复现证据。

日期：2026-10-15。基于当前未提交工作区，对照 ADR 0025 交接时的源码摘要检查后续增量。结论：有实际进展，但存在两项 P1 问题及一项基准计算问题，M1 继续 partial。本轮只评审和新增证据，没有修改实现、旧报告或历史截图，也未打开原用户数据库。

## 发现

### R1 / P1：RAW 分支绕过像素限制，普通转换不保证提取嵌入预览

位置：`between-frames/src-tauri/src/photo_inspection.rs:61–73, 135–157`。

RAW 仅凭扩展名分支，直接跳过 3200 万像素约束；`sips -s format jpeg` 是格式转换，该调用没有提取嵌入 JPEG 的明确约束、输出像素限制或产物尺寸检查。因此可以返回全尺寸图，并让浏览器解码超过原有内存边界的图片；两图对比会放大内存占用。

隔离复现：Pillow 生成 7000×5000 的灰度 TIFF（35,000,122 字节），文件名为 `oversized.dng`。真实 Rust ImportManager 导入成功、无失败；随后 `get_original_photo` 返回 `kind=embedded_preview`，实际产物 JPEG 仍为 **7000×5000 / 3500 万像素**。该数据是临时生成的格式边界测试图，没有真实用户照片。

建议：采用能明确提取嵌入预览的能力，或受像素/内存约束的派生预览解码；核验输出格式、尺寸和来源类型后再授予 asset 访问。不能仅按扩展名放宽解码边界。增加改名 TIFF、大尺寸 RAW、缺少嵌入预览等回归；RAW 预览的 UI 页脚也应使用预览名称，避免同时显示“原图 100%”。

### R2 / P1：瘦回执重放替换整个项目，破坏旧回执语义与版本一致性

位置：`between-frames/src-tauri/src/command_handler.rs:123–132`。

新回执清空 `project.events` 后落库，重放时却用 `snapshot_tx` 替换整个 `result.project`。这同时覆盖了已持久化的原始标题、照片决策、序列、版本与 revision，而核心 `result.revision` 仍停在旧命令。ADR 0026 已声明改变语义，但这与 ADR 0023/0025 的既有幂等兼容保证不同，不能称为旧语义不变；现有回归也被改为只比较核心字段，漏掉了这个差异。

隔离复现：命令 A 把标题改成 A，返回 `revision=2 / project.revision=2`；命令 B 再改为 B；用 A 的原始完整 envelope 重放，返回 **`revision=2 / project.revision=3 / title=B`**。回执体与首次结果不同。

建议：保留瘦回执已存的历史业务快照，仅通过事件截止游标等方式补齐该命令当时的历史，恢复同 envelope 首次/后续编辑后/重启后的回执一致性测试。若要引入“旧命令回执 + 当前投影”新协议，应显式版本化并让调用方区分两个版本字段，不能直接替换旧接口语义。

### R3 / P2：长期增长基准命令数计算错误

位置：`between-frames/src-tauri/tests/perf_baseline.rs:112–160, 177–190`。

当前循环每轮执行两组，每组是 1 条决策 + 两次 Undo/Redo（4 条），总计 **125 × 2 × 5 = 1250 条 GUI 命令**，不是 500 条。吞吐仍使用 `500 / elapsed`，每百命令增长仍除以 5，导致两个归一化指标相差 2.5 倍。ADR 0026 和工程导航的“63.7MB / 500 命令”也因此不能由该代码支撑。

建议：实际累计成功命令数，或通过执行前后的回执行差值核验；按真实次数计算吞吐与增长。统计 SQLite 占用时说明主文件/WAL 的范围或 checkpoint 方法，重新保存原始输出并更新报告。本轮没有重新运行 ignored 增长基准，不认可现有数字已被独立复现。

## 验收边界与建议顺序

1. 先修复 R1/R2 并补真正能发现它们的断言；R3 与文档数字同步修正。
2. HEIC/RAW 测试目前依赖 `/tmp` 私有样本，缺失时直接返回 success；ICC 检查也允许跳过部分分支。需提供可复现素材来源/准备步骤，并让未执行分支显式显示为未验证，不能只引用总通过数。
3. TIFF/HEIC 后端返回路径，尚不能替代 WKWebView 实际显示验收；CR2 一个样本不能证明所有 RAW 仅提取嵌入预览。保留 ICC 字节证明未重编码，不能据此宣布色彩显示准确。
4. 本轮新增目录内只有 GUI 指标和两份场景 JSON，未见 500 命令增长基准原始输出、原生 500 图完成证据。后续优先补原生 release 完整旅程、真实高像素素材及可获得的硬件采样；低端设备和校准显示器继续标为外部未验收。
5. `TEST-REPORT.md` 顶部仍是上一轮摘要，原图报告的第二轮增量与末尾剩余项存在矛盾；实现修正后统一更新当前入口。不要提前进入新的 M2。
