## 取得明确批准后的执行顺序

1. 只读核对生产状态与既有邮件/模型配置，仅记录是否配置，不输出密钥。
2. 为独立数据库/预览保存并核验备份，保留当前镜像/部署配置；不执行 compose down、全局 prune、删库或删卷。
3. 固定镜像导入、显式增量迁移 0014/0015，按当前最小权限角色验证。新 API 会拒绝不相符 schema。迁移凭据与运行时应用凭据的彻底分离仍需实际部署配置收口，不能仅靠指南宣称完成。
4. 邮件 Key 仅写入服务器私有环境配置，不放源码、镜像、argv 或日志。通过 Resend 核对可用发件身份，选择已验证的合法 From；没有可用发件域则暂停邮件启用，不伪造域名，也不自行更改 DNS。
5. DeepSeek Key 仅使用项目已授权的安全配置；没有有效服务端凭据/余额则保持 AI 关闭，并报告实际状态。不从桌面用户收集个人 Key，不使用兼容网关替代既定服务。初始额度默认 0，明确配置/分配后才可真实调用。
6. API/Web 同批替换；仅向用户提供的测试邮箱发送一次真实验证码，验证回执/收件/登录/退出，再以明确有限额度和授权的仓库测试样片验证模型协议、图像和账本。真实供应商调用范围/额度在执行前明确，专业质量仍另评。
7. 验证公网 TLS、账户、会话撤销、权限、额度不足与重启保留；不把 HTTP200 或邮件 API 接受当成完整登录/真实收件证明。

## 停用与回退

发生异常先停用 AI 配置，保留账本和不确定请求；必要时保留维护状态，不重复发模型请求。完成 0015 后不能直接启动只认识旧 schema 的 API 镜像；不删除迁移登记/表来强行回退。恢复必须使用已验证的独立备份方案并另行确认，不能覆盖现有库试错。
