## 当前执行顺序

1. 收口 M3 现有链路：预算内完成、授权真实照片、可复核工具/照片引用、状态与原图保护；保留所有失败尝试。
2. 组织真实创作任务与独立评审，使用 `between-frames/tools/agent-eval/README.md`；代码或单个相机目录不能自动变成 30 个不同创作任务，也不能代替真人判断。尚无专业目标/评委时，工程冒烟不计质量基线。用户已授权模拟真人：可用明确标记的 AI 角色继续流程验收和工程开发，真人/模拟分数分开，不伪造参与者、同题基线或偏好记忆。
3. 以评测证据修复观察/检索/多模态路由/记忆问题并回归；明确继续/停止标准。M3 未验收，不以增加云 UI 或支付功能宣布产品已完成。
4. 已有 M4 本地 HTTP 切片仅修复并保留回归（见 V2-M4-LOCAL-BOUNDARIES-TEST-REPORT.md），不算阶段通过。M3 达到继续门槛后，继续完成 M4 首个完整产品旅程：独立本地开发环境的登录 → 项目 Grant/Invite → 受邀 Web 读取获授权预览 → 撤销即拒绝。随后再接真实 Promotion 和 Postgres 单权威。不能把现有 openyc 项目容器当作本项目服务。
5. 按 M5→M6→M7 推进，每阶段交付可运行结果、权限与异常测试、验收记录、剩余问题；涉及线上 schema、生产部署、支付资金等高风险操作先提供具体方案与影响供用户确认。

## 云资源状态的证据来源

历史用户只读核对曾确认腾讯云有其他项目 PostgreSQL 实例和空的 `betweenframes` 数据库、当时没有本项目 API。此后共享仓库出现声称部署的提交，但本轮未登录服务器/调用生产 API，未获得与源码版本绑定的可复核部署产物；当前状态记作“未核验”，不能沿用旧“绝无部署”或从新标题推出“已全部上线”。仓库已有 cloud/ SQLite 本地服务与协作端点，不等于 Postgres 权威；新增静态页面也须按具体授权旅程验收。本轮未执行线上 DDL或读取修改其他项目数据。后续部署须隔离其他项目数据库权限、密钥和容器资源，并按高风险操作确认要求执行。

本清单不承诺工期或完成百分比。真人、竞品权限、经营主体/支付资格与线上审查是实际门槛；它们不会由测试夹具自动变为完成。
