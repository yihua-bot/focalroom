## 当前执行顺序

1. 收口 M3 现有链路：预算内完成、授权真实照片、可复核工具/照片引用、状态与原图保护；保留所有失败尝试。
2. 组织真实创作任务与独立评审，使用 `between-frames/tools/agent-eval/README.md`；代码或单个相机目录不能自动变成 30 个不同创作任务，也不能代替真人判断。尚无专业目标/评委时，工程冒烟不计质量基线。
3. 以评测证据修复观察/检索/多模态路由/记忆问题并回归；明确继续/停止标准。M3 未验收，不以增加云 UI 或支付功能宣布产品已完成。
4. M3 达到继续门槛后，M4 首个垂直切片：独立本地开发环境的登录 → 项目 Grant/Invite → 受邀 Web 读取获授权预览 → 撤销即拒绝。随后再接真实 Promotion 和 Postgres 单权威。不能把现有 openyc 项目容器当作本项目服务。
5. 按 M5→M6→M7 推进，每阶段交付可运行结果、权限与异常测试、验收记录、剩余问题；涉及线上 schema、生产部署、支付资金等高风险操作先提供具体方案与影响供用户确认。

## 云资源状态的证据来源

用户在本轮提供了另一次只读核对结果：腾讯云有其他项目的 PostgreSQL 实例和空的 `betweenframes` 数据库；没有已部署的 Between Frames 云 API。本轮未登录服务器、未执行 DDL、未读取或修改其他项目的数据，也未将该说明当作已验收的应用服务。后续部署须隔离其他项目的数据库权限、密钥和容器资源。

本清单不承诺工期或完成百分比。真人、竞品权限、经营主体/支付资格与线上审查是实际门槛；它们不会由测试夹具自动变为完成。
