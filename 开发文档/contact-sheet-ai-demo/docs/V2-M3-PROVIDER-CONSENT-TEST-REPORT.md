# M3 实际服务图像授权隔离验收

日期：2026-10-17（Asia/Shanghai）。接续 [作者记忆](V2-M3-AUTHOR-MEMORY-TEST-REPORT.md)，设计见 [ADR0038](ADR/0038-m3-provider-bound-image-consent.md)。本轮范围为供应商收件人授权边界；M3 整体仍 partial。

## 功能结果

- 旧图像授权只记录通用 openai，切换兼容服务端点后新任务可能继承旧同意。现在正向授权按实际 Adapter/端点摘要/型号标识生成收件人命名空间；不同端点、路径或型号不能共用，密钥轮换及尾斜杠规范化保留同一收件人。
- 新增 AiConfig.consentProvider，来源为冻结实例；界面展示服务地址、型号、1400px 预览范围和不转授其他服务的说明。原生 IPC 与 harness 共用 AgentEngine.set_consent，过时的界面标识在写入前拒绝并提示刷新。配置失效或没有服务仍可禁止。
- 任务显式 consentId 必须属于项目且为新的收件人授权；绑定模型时再核对实际收件人，错误显式授权在任何模型 HTTP 前拒绝。隐式项目授权只查当前 model_binding 的收件人；旧通用正向授权不推断、不升级、不用于上传。
- 禁止云端图像撤回本项目全部服务授权，旧 deny 保持有效；之后明确批准 A 不会恢复 B。多个服务可分别明确批准，但本轮没有自动 fallback 或跨服务执行。
- 管理入口可主动打开授权卡，取消不改变授权，管理本身不创建任务；从视觉委托流程批准后，单次/项目模式都携带明确回执 consentId 发起任务。通信重试沿用 requestId，回执检查项目/收件人/模式/配额，业务拒绝不重试。
- HTTP 自动重定向关闭，307 等非成功响应作为服务错误，不能将预览和认证自动转交 Location。视觉预留账本附非秘密 recipientId；范围、配额、预算、观察缓存和未知结果保留规则继续生效。
- 复用现有 provider TEXT、授权回执、model_binding 和 Runtime，没有新增 schema、依赖或服务。正式选片、作品序列与人工记忆不由授权操作修改。

## 验证

全量 verify-all --skip-keychain exit=0：**181 项桌面 Rust、13 项本地云测试、180 项 Vitest、16 项预览 E2E、6 项真实后端 E2E**，契约/类型/Lint/fmt/严格 Clippy 均通过。桌面 13 项 ignored、钥匙串写删 1 项 filtered，未计作通过。

之后截图 QA 只调整 AIPanel 界面与其测试，Rust 生产代码不变；最终前端类型/Lint/180 项单测/16 项预览及整个 6 项真实后端套件再次 exit=0（后端 1.4 分钟）。新截图已检查；90 张本轮开始时已有 PNG 字节全部保留，恢复 25 张测试产物，不从 HEAD 覆盖旧工作区。243 个归档源码/契约/测试文件摘要一致。完整日志、首次定向失败、QA 修改清单及摘要见 evidence/v2-m3-provider-consent/。

独立原生 debug 构建成功（58.59MiB，studio.betweenframes.m1reviewfixes），NaturalLanguage 弱链接检查通过；在全部 E2E 结束后顺序构建，未启动原生窗口或用户库。构建哈希及元数据已归档。Prompt 仍 m3-openai-8 / m2-mock-2，视觉/向量缓存版本不变；无新真实 Provider 或原生向量专项验收。

新增 7 项 Rust 用例，原 28 项视觉测试保留并调整为对实际测试收件服务分别授权；新增 7 项前端用例。直接观察、完整 Runtime、真实本地 HTTP、前端服务边界和现有 GUI/harness 均有覆盖。没有使用真实 Provider 或 LUMIX 素材。

| 场景 | 验收内容 |
|---|---|
| 端点/型号隔离 | A 的授权不能用于 B；错误显式 ID 在任何 HTTP 前拒绝；无匹配项目授权零图像；明确批准 B 后才有实际本地 HTTP 图像请求 |
| 密钥/配置 | 换 key 和尾斜杠身份一致；换端点/型号身份不同；过时 UI 标识拒绝且零授权落库；无服务/无效能力仍可禁止 |
| 旧库兼容 | 直接构造旧 openai 授权，不回填来源；新任务不能绑定/沿用；重新明确授权后才可上传 |
| 全局禁止 | 多服务均失效，重新批准一方不恢复另一方；配额仍按实际传输与原预算控制 |
| 事务与幂等 | 同 requestId 返回同授权 ID，跨收件人同 ID 冲突；替换授权插入故障时原授权与回执保持一致；归档项目拒绝 |
| 重定向 | 本地 307 的原服务收到测试图像，Location 目标收到 0 请求；错误不可重试；未读取任何真实照片 |
| 前端 | 服务/型号与范围可见、显式回执 ID、异收件人/已撤回授权不跳过对话框、配置变化刷新、不误启动任务、离线禁止入口 |
| 原有保护 | 视觉计量/缓存/预算/取消恢复、身份绑定/区域/能力组合、作者记忆/草案正式隔离继续回归 |
| GUI/harness | 离线管理卡正向授权按钮禁用；禁止请求落库并跨进程重启保留；正式项目/Agent 投影/测试源 hash 不变，页面零外部请求 |

截图 QA 另修正离线卡沿用“将向 Mock 上传”的提示，复用 info-card 样式并补取消入口；取消和管理不委托的断言保留。Rust 生产代码未改，最终界面版本重新执行全部前端检查和两个 E2E 套件，结果见最终记录。

首次新增前端用例有测试夹具问题：正文和诊断都显示模型名称，单项文本查询重复；原 beforeEach 返回 mock 函数，被测试框架用作清理函数，设置 rejection 后导致额外失败。已改唯一角色查询与无返回的 beforeEach；功能断言保留。修复后定向测试通过，原始定向失败日志保留，不把测试夹具失败描述成生产服务故障。

## 复现

在 between-frames 目录依次运行：

    bash "scripts/verify-all.sh" --skip-keychain

所有 HTTP 测试使用显式 loopback Provider 和生成测试素材；默认忽略的真实 Provider/照片/原生向量测试不计通过，钥匙串写删单独跳过。E2E 结束后才做独立原生 debug 构建，不能并行触发 Vite 页面刷新。

## 剩余问题

- 此切片完成兼容 Adapter 的实际图像收件人隔离，尚未完成多 Adapter、低价观察/高能力策展分工、跨服务 fallback 执行、服务条款版本和区域/质量证明。配置备用密钥不构成终用户同意；旧 provider_fallback 辅助模块不能作为授权边界。
- 图像授权不等于文本或作者记忆的跨服务授权。云作者记忆仍禁用；Creator/Workspace 私人记忆身份隔离仍待开发。
- 关闭重定向只控制本应用 HTTP 客户端，不能保证服务端内部处理/转发。型号标识不保证固定模型权重；驻留、收费与专业质量均需独立证据。
- 撤权阻止后续授权预留，不能撤回已发送/已进入预留的请求，也不清除历史观察、任务回执、缓存、备份或对端数据。
- 本轮未打开原用户库、执行新迁移/依赖更新、使用真实 API Key、部署或 Git 提交推送。M3 的正式摄影任务、专家/竞品评测，以及 M4–M7 的剩余门槛保持单列，详见 [剩余计划](V2-REMAINING-PLAN.md)。
