## 问题与修复

1. **视觉响应未在本地校验 schema**。`strict: true` 只是发给提供方的请求，原实现解析 JSON 后便接受结构。先补测试，实测 `missing_facts 必须被拒绝` 失败，再修复 Provider：复用已有共享 schema 校验器，拒绝缺字段、错误类型、空事实数组、额外字段、重复照片和非对象根节点。先校验再添加内部 `model_id`，也避免数组根节点在字段赋值时 panic。
2. **旧缓存可绕过新校验**。缓存命中必须符合相同结构且 `photo_id` 与当前照片一致；无效缓存视为未命中。没有绕过 consent 或预算的重新上传入口，也不删除旧记录或改历史回执。
3. **真实模型测试存在假通过条件**。旧测试接受 `paused` / `needs_input`、零草案以及缺 key 时直接返回；视觉测试只检查非空字符串，未证明严格结构。现改为显式执行时要求 key、端点、模型齐备；任务必须在预算内进入 `review_ready`，引用本任务真实的待评审草案，目标两张照片必须唯一、存在且位置正确。正式项目完整投影必须不变。纯文本结束、暂停和等待输入都不计本任务成功。
4. **验收层级与计量纠正**。无图像授权的主循环测试只要求元数据草案，不再要求判断色彩。直接调用 `observe` 的测试明确为 Provider 协议冒烟，不声称验证引擎 consent/配额；要求单张生成图的准确 ID、有效结构及正数 `usage.total_tokens`。主循环当前持久化的是预算估算，不把不存在的 `tokensIn` 字段当作实际 token；中文日志按字符截断，避免 UTF-8 字节边界 panic。

生产代码复用现有 schema 与计量/授权通道，未新增依赖、迁移或工具。无效模型响应已发生的上传仍扣配额，任务失败，观察不落库；未改变合法的澄清、暂停与无操作任务状态，只收紧指定选片任务的成功判定。
