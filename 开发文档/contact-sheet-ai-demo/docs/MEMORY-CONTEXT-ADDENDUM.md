# 记忆与上下文补充约束

来源：用户 2026-10-13 提供的粘贴文本，建议后续固化 Memory Engine & Context Engineering v1.1。下列约束进入后续实现；本轮 M0 不实现记忆引擎或模型调用。

- L0 选区与任务、L1 项目事实、L2 人工证据、L3 可纠正偏好假设分层；SQLite 保存权威事实，模型不持有唯一状态。
- 记录人工保留/淘汰/比较/草案改动/理由；Agent 自己的候选不构成人类偏好证据。单次无理由操作不产生跨项目假设。
- 证据按因果操作去重，撤销/重做/重复提交不增加独立支持次数。纠正优先，冲突保留反例；过时只降低检索优先级，不直接判失效。
- 假设默认 project_local；跨项目使用 opt-in。删除/纠正需失效检索缓存并停止未来引用，产品如实说明日志/备份保留边界。
- ContextBuilder 组装 system/policy、task、GUI、相关记忆、视觉观察、执行上下文。先按项目/照片范围、权限和有效状态过滤，再 FTS5 检索、相关性/确认/证据/时间/作用域排序、去重及预算裁剪。
- 12,000 文本 tokens 及示例分配是可调实验建议，尚未作为固定默认；图像费用和输出预留独立计入预算。v1.0 的任务轮次/调用/时间/图像/费用上限继续由后端控制。
- 摘要与 checkpoint 保留目标、明确约束、权限、项目 revision、草案/观察/证据 ID、完整 call_id 协议关联、未决审批和剩余预算。只压缩冗余过程，不删正确恢复所需信息。
- 浏览、评分、选片、拖动不启动模型；事件证据整理可异步进行。Memory Precision、Correction Compliance、Context Efficiency 使用授权测试集评估，不编造目标数值。
- 第一版使用自定义 Evidence/Hypothesis + SQLite/FTS5，不引入独立向量库、分布式记忆服务或微调。

M2/M4 开始前补算法级规范和确定性测试：提取/去重、检索排序、冲突、纠正与删除传播、压缩完整性、恢复与指标；本文件不是已完成的算法实现。
