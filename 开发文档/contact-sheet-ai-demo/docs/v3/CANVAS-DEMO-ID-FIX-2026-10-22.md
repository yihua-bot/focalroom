# 演示项目画布编号兼容修复

日期：2026-10-22。检查基线：`b240214`。本报告只覆盖本次画布报错，不表示 v3 全部 Gate 或发行验收完成。

## 问题与证据

用户反馈「画布操作内容无效，请重新选择后重试」。该提示可能由不同的请求校验失败触发。本轮确认并复现了其中一个确定的问题：正式客户端内置演示项目使用 `seed_demo.rs` 中的稳定编号 `demo-first-walk`，但新增画布协议将项目编号误限定为 UUID。

修复前，新增前端契约测试、待确认恢复测试均失败，错误包含 `projectId: Invalid UUID`；真实 SQLite Store 测试经正式 `ensure_demo` 初始化演示项目后，创建画布也返回 `VALIDATION_ERROR / 画布操作标识无效`。因此，仅去掉前端提示或替换项目编号都不能正确解决问题。

## 修复范围

- 前端请求和回执共用同一项目编号规则：非空、最长 160，与现有项目协议兼容。内置演示项目与普通 UUID 项目都可使用。
- Rust 命令入口同步接受原有项目编号。新命令、画布和操作编号保留原有 UUID 要求；归属、权威、归档、版本与幂等检查继续生效。
- 校验失败时，界面使用「这次操作未能保存，请重新打开画布后重试。」；内部校验详情保留为错误原因，不再直接展示代码字段和英文校验表达式。
- 无数据库迁移，无项目编号改写。测试只访问新建临时目录和 SQLite 库。

采用最小协议兼容修复，不增加演示项目专用写入通道。所有项目继续使用同一正式画布命令链路；测试接入只位于集成 harness，不进入正式客户端命令注册。
