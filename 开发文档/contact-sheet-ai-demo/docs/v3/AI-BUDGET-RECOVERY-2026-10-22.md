# AI 选片预算拦截与恢复修复

日期：2026-10-22。本报告记录本轮源码修复、测试和两家服务的可用性验证，不代表所有 v3 Gate 或生产发行验收完成。

## 已解决的问题

原提示「视觉请求预留超过图像、费用、工具或时间预算；未上传」由四种不同条件共用，用户无法判断原因。检查还发现三处会导致正常任务被拦截或重复暂停的实现问题：

1. 前端把整次任务的图片发送额度压到照片张数。两张照片先观察、再比较，后一次发送可能立即触顶。
2. 正式托管路线的地址是 FocalRoom 网关，费率识别却只认官方地址，因此固定的 DeepSeek 路线误用未知服务的通用高价估算。
3. 「继续」只把步骤额度恢复到默认值；已经消耗完默认额度时，再点继续仍提交相同上限。

视觉分析还始终为最大回复长度预留费用；即使较短回复可以完成请求，也可能提前拒绝。本轮新增可负担的回复上限计算，并由本地 HTTP 服务验证实际发送值。

## 最终行为

- 分别报告照片次数、费用、步骤、等待时间、模型回合、内容大小和总内容额度不足。通过结构化 `budgetIssue` 传给界面，不从中文提示猜原因。
- 停止原因和任务暂停、检查点在同一事务记录，复用现有追加式 `agent_steps`，不增加数据库迁移；应用重启后仍能显示。主动暂停或其他原因覆盖状态后，不显示过期的额度原因。
- 时间不足显示「延长时间并继续」；步骤或回合不足时，「继续」会实际增加可执行额度。保留后端硬上限，不放宽费用和图片授权。
- 模型已经返回结果后才达到时间、费用或内容限制，也分别记录原因；已收到结果的超时可以明确延长后继续。网络超时、结果未确认与已知完成分开处理，不误称尚未发送。
- 照片次数、费用或内容过多时，提供「调整照片范围」：填回原要求并切换到选中照片，等待用户重新发送；不自动创建任务、重新上传、取消旧任务或提高费用限制。
- 明确展示已经发送的次数、本次需要的次数和本次上限。「未发送」只描述被拦截的这次照片请求；此前步骤仍可能产生用量。
- 对历史混合报错提供可读提示。对超时、传输结果不明或此前上传失败，说明可能重复消耗，不提供直接继续上传的按钮，也不声称未发送。
- 图片设置改为「本次分析次数上限」，按任务累计发送次数授权；同一照片再次发送也计数，缓存命中不计上传。任务允许访问的照片集合仍由原有授权范围校验，增加次数不扩大照片集合。
- 预览发送说明使用当前服务信息，不再把所有服务写死成 DeepSeek。新增提示同步中文、英文、日文、韩文。
- 每个待执行工具读取最新任务用量，视觉预留仍在写事务中再次检查；不能用循环开始时的旧用量绕过限制。
- 固定的官方 DeepSeek 托管路线使用已有的版本化费率卡；未知端点和其他模型继续使用保守规则。没有把腾讯聚合服务擅自套成官方价格。
- 只收紧本次视觉回复长度，不抬高任务额度，不减少请求中的照片；最小结构化回复仍超限时，明确暂停。

实现复用现有任务状态、检查点、回执和额度事务。错误详情保持为可选字段，普通错误的原有输出不变；界面不会展示内部工具名或协议字段。

## 服务与密钥验证

用户提供了两家服务凭据，并确认腾讯云地域为广州。本轮使用官方 HTTPS 地址验证，验证脚本从隐藏输入读取凭据，输出和本报告不包含密钥，未写入仓库或安装包。

| 项目 | 实测结果 | 边界 |
|---|---|---|
| 腾讯云 TokenHub 广州模型列表 | 200，返回 119 个模型 | 查询成功本身不证明推理余额充足 |
| 腾讯云视觉请求 | `deepseek/deepseek-v4-flash-vision-exp`，200、completed，报告 363 tokens | 仅一张生成的 32×24 色块图；只验证接口和计量返回 |
| DeepSeek 官方模型列表、余额接口 | 均 200，`is_available=true` | 不保存或公开余额数值 |
| DeepSeek 官方视觉结构化请求 | `deepseek-flash`，200、completed，JSON 返回 `color=red`，报告 324 tokens | 仅一张生成的 32×24 色块图；不替代摄影选片质量评测 |

合计真实视觉请求 2 次、生成图 2 张、用户原图/预览 0 张。没有执行真实照片策展或真人评测，也没有因此给用户账户发放额度。

本轮优先沿用已核对余额及视觉能力的 DeepSeek 官方路线。腾讯云具备可用备选接口证据，但**现有正式托管策略仍绑定 DeepSeek，生产端尚未接入腾讯云自动切换**。不能把腾讯的 Key 填入 `FOCALROOM_DEEPSEEK_API_KEY`：现有服务会把它发送到 DeepSeek 官方地址。后续若启用腾讯云，必须补齐对应服务策略、任务身份和发送说明，再为新任务选择；旧任务不能静默换收件人，结果不明的请求不能换服务重传。

官方依据：

- [腾讯云接口地域、鉴权与模型列表](https://cloud.tencent.com/document/product/1823/130078)：按已确认地域使用广州接口，不跨地域猜测。
- [腾讯云 Responses 协议](https://cloud.tencent.com/document/product/1823/135873)：核对图片、函数工具及结构化输出字段；实际支持以本轮调用结果为限。
- [DeepSeek 余额接口](https://api-docs.deepseek.com/api/get-user-balance/)：`is_available` 表示余额是否足够调用。
- [DeepSeek 模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)：2026-10-22 再核对 Flash 视觉支持，以及非缓存输入峰时 $0.30/M、输出峰时 $1.20/M，与现有版本化费率卡一致；预算估算仍不是账单。

## 验证

证据目录：[`evidence/ai-budget-recovery-2026-10-22/`](evidence/ai-budget-recovery-2026-10-22/)。最终统计已按日志核对。

- 前端：47 文件、318 项通过（`frontend-complete.log`）。
- 浏览器真实 Rust Store：1 条完整旅程通过，46.6 秒操作、总计约 1.5 分钟。实际创建低回合额度任务 → 确认具体暂停原因 → 重开界面 → 继续同一任务且额度实际增长 → 生成两份草案 → 人工冲突、部分采纳、撤销、进程重启。照片与费用上限保持，源文件校验一致，页面错误与外部浏览器请求均为 0。
- Rust：281 项通过、15 项显式 ignored、0 失败，37 个结果段（`rust-final.log`）。
- 视觉收紧测试使用本地 HTTP 服务：两张照片、20 美分任务上限，实际视觉请求恰好 1 次、回复上限低于 8192、两条观察入库；原任务费用与输出配置没有被提高。
- 四种视觉限制分别校验；精确等于额度可执行；超限不写上传预留、不扣图像授权。原有跨服务、撤权、上传失败、重启不重复传输测试保留。
- 类型、Lint、严格 Clippy、格式、生成契约、Desktop/Web 构建均已通过（`build-complete.log`、`lint-complete.log`、`clippy-final.log` 等）。`verification.json` 保存代码和最终日志摘要。

初次测试保留了旧文案断言不匹配、测试库不支持 `exact` 参数、并行负载下的超时及单图夹具无法承担前置编排的失败记录。已分别改为结构化原因断言、正确的精确名称匹配、降低测试并行度（不延长断言超时），并以两图/20 美分构造真正覆盖视觉回复收紧的场景。最终日志与失败记录分开保留。

浏览器集成桥没有实现原生菜单语言命令，日志含已捕获的对应警告；本轮浏览器结果不计系统菜单验收。系统菜单的用户确认见独立菜单栏报告。
