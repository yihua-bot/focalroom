### 2. 画布列表请求没有传项目

位置：`apps/web/src/shared/BoardViewer.tsx:34`；对照 `apps/api/src/server.ts:102`、`apps/api/src/boards.ts:90`。

前端调用 GET `/boards`，服务端却将 query.project 交给必填字符串解析。前端随后 catch 丢弃异常，用户看到空画布列表，无法进入实际画布。

### 3. 图片预览请求没有对应路由

位置：`apps/web/src/shared/BoardViewer.tsx:55`。

新增 GET `/assets/{assetId}/preview-url`，当前 API server.ts 没有该路由。现有媒体流程是项目内 preview ticket，再读取媒体 URL；不能将 SourceAsset ID 直接当作现有照片票据接口身份。需要项目内资产到授权预览的真实映射，以及可见的失败状态。

即使修好列表请求，当前图片请求仍会失败并被吞掉，留下占位符。因此“已显示真实预览”的描述没有现成端到端证据。

### 4. 撤销日志写入失败仍提交业务修改

位置：`src-tauri/src/canvas.rs:179`、`:232`、`:697`。

三处均使用 `let _ = Self::log_canvas_op(...).await`。SQLite 语句错误可能只终止该语句而不终止整个事务；随后 commit 仍执行，业务操作可能成功但没有撤销记录。这违反“操作与历史同事务成功或回滚”的要求。应传播写日志错误，并以故障注入证明业务修改和日志同时回滚。

### 5. 锁定后撤销会丢失恢复机会

位置：`src-tauri/src/canvas.rs:1037`、`:1072`。

撤销移动只更新 locked=0 的节点，却不检查 affected rows，随后无条件设置 undone=1 并返回 true。对已移动再锁定的节点，坐标未恢复，撤销记录已被消费；多节点操作还可能只恢复部分。

本次在内存 SQLite 使用实现中的相同 SQL 复现：x=10、locked=1，撤销 dx=10，节点影响行数 0，x 仍为 10，日志 undone 已变为 1。此证据验证该 SQL 路径，不冒充执行了完整 Rust 方法。应定义并测试冲突/锁定时的原子失败，不以跳过当成功。

新的 canvas_op_log 通过 UPDATE 修改 undone，且没有不可变触发器，因此准确名称是“可变的私有撤销栈”；它保持了 command_events 不被修改，但自身不是严格 append-only 审计日志。

### 6. Agent 问题包含协议与权限，不只是请求大小

位置：`contracts/agent-tool-contracts.json:521`、`src-tauri/src/agent/policy.rs:12`、`:102`、`src-tauri/src/agent/tools.rs:627`。

本次实际解析 JSON 契约得到：

| 工具 | 实际注册情况 |
|---|---|
| create_board_draft | 已注册，required 只有 title，无 project_id |
| place_photos_on_board | 已注册，required 为 board_id/placements，无 project_id |
| get_board | 已注册，required 只有 board_id，无 project_id |
| group_nodes | 未注册 |
| create_sequence_draft | 未注册 |

ToolRegistry.model_specs 当前不按任务过滤，直接发送契约中的全部工具。所以前三个不是“未发给模型”：它们已发送，但 strict schema 不允许 project_id，而 PolicyGate 要求每个调用的 project_id 等于 task.project_id，两者冲突。

此外 create_sequence_draft 的 INSERT 缺 drafts 所需 task_id/base_revision/state/summary；后续 INSERT 使用 draft_items.action，而实际列为 proposed_action，且 rationale 必填。新增处理函数存在并不等于这条运行链路成功。evaluate_sequence 在 canonical 处理后进入 evaluate_draft，新增同名分支不是当前调用实际路径。
