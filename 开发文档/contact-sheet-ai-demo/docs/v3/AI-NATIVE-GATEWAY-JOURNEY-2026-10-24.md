## 已实现和验证的路径

`真实Rust AgentEngine → 本机HTTP → 真实NestJS → 临时PostgreSQL → 本机模型替身 → 原编号查询 → 明确继续`。

- m1-harness增加仅供integration-harness使用的托管会话入口，复用正式CloudAuth、AgentEngine.request及固定账户协议。来源必须是精确回环HTTP，认证读取禁止重定向且有超时；会话只在测试子进程内存中，不读写系统钥匙串，不进入SQLite、命令行参数或测试输出。
- 新hosted-ai素材配置只生成一张32×24色块，不读取LUMIX或真实摄影作品。普通200/500图回归配置保持原行为。
- GUI任务请求改经AgentEngine.request，覆盖账户绑定、暂存许可冻结和正式取消路径；已有Mock浏览器旅程继续使用原剧本。
- 增加可重复的五条跨语言旅程，并接入verify-all及`test:ai:native`。每次创建独立临时PostgreSQL和SQLite；模型替身仅返回固定协议结果，不访问外部供应商。

| 场景 | 必须验证的结果 |
|---|---|
| 客户端在排队后被SIGKILL | 重开保持interrupted，查询原编号仍pending；替代消费者处理后结果可找回，但不会自动继续任务 |
| 用户明确继续 | 同一视觉工具仅回放一次；一条观察、一条结算、一次图片上游调用；两轮文字加一次图片的替身计量共90 tokens，服务端预留归零 |
| 取消尚未发出的图片请求 | 返回已撤回，密文清除、图片上游调用为0、只保留先前文字的30 tokens；相同取消命令回执可重取 |
| 取消已发出的请求 | 返回已开始处理；等待中的预留不能提前退款，后续按60 tokens结算；本地任务保持取消、不将迟到结果写入照片观察 |
| 换号或原会话撤销 | 其他账户不能查询旧任务；未发出的排队请求因原会话失效被拒绝并清除密文 |
| 服务支持暂存但用户未选择 | 完成普通异步图片流程，fr_ai_jobs没有记录，不追认暂存许可 |

表中的90/60/30是固定替身的token记录，用于校验账本，不是供应商真实计费或摄影质量结果。五条测试中，第一条同时包含“找回”和“明确继续”。原项目、照片决定及生成源图SHA保持一致；图片工具回执关联实际photo_id、源文件hash、模型及观察缓存版本，且不包含data URL。

## 复现

在between-frames目录运行，依赖本机已有Node、Rust、PostgreSQL测试工具：

```sh
cargo build --manifest-path "src-tauri/Cargo.toml" --features integration-harness --bin m1-harness
npm run test:ai:native
```

verify-all先构建target-v1，再用相同目标目录执行组合测试。测试不需要生产账号、供应商密钥或Mac解锁；不会触发系统钥匙串授权窗口。
