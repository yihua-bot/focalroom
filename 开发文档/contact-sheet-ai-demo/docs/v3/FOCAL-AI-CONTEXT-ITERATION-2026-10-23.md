# Focal AI：创作上下文、跨轮修订与知识记忆

日期：2026-10-23。接续 `FOCAL-AI-V2-IMPLEMENTATION.md` 的 S2 / S4，并补充 S3 / S5 的自动化验收入口。代码基线是共享工作树 `b108065` 加未提交改动；包含此前 S1 与 v3.1 审稿工作，不将第三方改动归为本轮新实现。

## 1. 可使用的行为

### 1.1 按需查询创作环境

Focal AI 在同一会话工具循环中可查询：

- 当前项目允许访问的画布目录、节点、位置、关联照片、当前版本及操作摘要。
- 已保存作品版本的真实选片决定、星级、备注与序列，而非只提供版本标题。
- 外部编辑 Variant / Rendition 的身份、来源、尺寸、位深与 ICC 元数据。
- 当前出版物规格、页面尺寸、出血、边距与照片框布局。
- 授权范围内的已有选片草案、草案内容，以及当前任务的完整工具回执。

查询按页返回，保留对象 ID、版本和来源。输出不包含原始文件路径。元数据、历史操作及编辑方法不是视觉证据；只有成功的视觉观察回执可显示“已查看照片”。

这里的“版本上下文”是对**现有持久数据**的统一读取。画布历史目前提供操作摘要，不提供任意历史时点完整几何快照；出版物读取当前版式，不虚构尚不存在的 Edition 历史、PDF/X 成品或专业色彩比较。

### 1.2 在上一轮方案上继续修改

1. 在真实选片或画布方案卡片点击“继续修改”。
2. 输入修改要求；引用的方案和版本在输入区可见，也可取消引用。
3. 后端核对项目、账户、模型服务、照片范围与版本，冻结父方案指纹。
4. Agent 调用分支工具创建当前任务的新方案，再编辑、送审。
5. 新方案显示修订来源；原方案与正式作品在人工采纳前不变。

父方案版本变化时明确拒绝，要求重新选择，不自动换到最新版本。正在运行的父任务不能作为修订来源。任务重启后父子关系和引用仍保留。

待审核方案继续分支时保留最初正式基线、节点来源及已删除节点的比较信息；“另存为独立方案”之后，这份独立作品成为下一轮的新基线。两种情况不能混用。正式采纳仍沿用审稿工作区及人工命令，不给 Agent 正式写入权限。

### 1.3 有来源的摄影方法

新增本地检索工具与 8 篇 FocalRoom 原创摄影编辑方法札记，覆盖观看节奏、创作线索、视觉事实、版本比较、摄影书、偏好、重复与非破坏性修订。每条返回原文、编号、作者、许可、版本和内容指纹，界面可展开核对。

这些是初始方法资料，不是完整摄影史、摄影书或外部文献数据库。未命中时不生成虚构引用。四语关键词支持检索；条目正文没有因此冒充四语完整教材。

### 1.4 经确认保存的审美记忆

Agent 只能提出待确认偏好，引用当前用户实际说过的话及适用范围。用户可编辑、保存到本项目或忽略；模型不能直接写入已确认偏好。

保存后复用现有记忆证据、修正、停用、排除、恢复及删除机制。重复确认不会产生第二份证据；已删除的偏好不会因再次点击旧建议而自动复活。界面重启后显示用户实际保存的文本。修正或停用后，旧会话不会把失效记忆通过历史文本重新带回。

新偏好按真实账户和照片范围隔离。跨项目作者记忆沿用原有显式本地授权规则；本轮没有新增云端个人长期记忆的授权或同步能力。

## 2. 工程设计与边界

复用 AgentEngine、PolicyGate、任务回执、检查点、记忆人工命令和画布草案，不建立第二套编排器。本轮新增工具为 `read_creative_context`、`fork_creative_draft`、`search_photography_knowledge`、`propose_preference`。

只对新 `StartConversation` 冻结新工具授权。旧任务的工具指纹及检查点保持兼容；新检查点额外绑定提示词、知识语料与父方案指纹。跨轮读取要求同一真实账户、同一不可变服务身份及被当前范围覆盖的照片权限；旧无归属聊天不自动外发。

大任务上下文压缩按完整工具批次归档，不按工具名称去重。近期调用和结果保持成对，原始完整回执持久保留，可按需读回。没有提高默认上下文、费用、图像或轮次上限。

新能力复用现有表，无新增迁移；共享工作树中的 `0032_editorial_merge_history.sql` 是此前 v3.1 工作，不是本轮新增迁移。测试使用临时数据库，没有升级正式用户数据库。

原则：用现有执行通道保持单一职责和权限边界；分支与只读检索分别处理；不为尚无数据的历史或知识预建空功能。授权校验、回执及记忆控制继续复用，避免重复实现。

## 4. 自动化验收的含义

离线 300 图场景运行真实 AgentEngine 与数据库，通过受控 Provider 分页查询 300 张生成素材，生成三份各 20 张的真实画布草案。验证方案身份、工具回执、上下文预算、重启和正式状态/源图哈希不变。模型夹具不分析真实照片，不能证明叙事质量或真实模型完成率。

浏览器场景覆盖“新方案 → 继续修改 → 两份真实方案 → 重启查看修订来源”，以及“查阅参考 → 偏好待确认 → 编辑保存 → 重启显示保存原文”。浏览器账户为隔离夹具，测试桥对本地 Provider 的记忆命令去掉模拟账户断言；生产 IPC 仍校验真实 CloudAuth 身份，账户拒绝场景由后端测试覆盖。

具体测试结果和证据摘要见同目录 `FOCAL-AI-CONTEXT-TEST-REPORT-2026-10-23.md`。未执行的验收不算通过。

## 5. 真实模型自动化验收（已准备，尚未执行）

入口 `focal_real_acceptance.rs` 默认 `#[ignore]`，缺少配置或素材时失败，不用生成图片补齐。

- 输入：300 张已授权 JPEG，原图只读；保留原图哈希。
- 第一任务：三条创作线索，每条 20 张，三份独立画布；最多上传 60 张受限预览。各方案入选照片必须有成功视觉观察，包含编辑说明。
- 第二任务：基于其中一份方案继续修改，不增加图片上传，父方案、正式项目和原图不变。
- 服务：固定已批准 HTTPS 端点与模型，无自动跨供应商回退。
- 预算：现有默认与 Standard 档位共同约束，单任务有效估算上限 50 美分，两任务估算总上限 1 美元；估算不是供应商实际账单。
- 证据：项目、任务、观察、用量、方案及哈希保存到仓库外临时私有目录，不保存密钥。

运行前须确认服务实际配置、能力与收件方，并按用户 AGENTS.md 对敏感外发取得明确批准。历史密钥不写进文档或命令。该直接 Provider 自动验收不替代正式托管账户/额度的生产联调，也不替代摄影师盲评。
