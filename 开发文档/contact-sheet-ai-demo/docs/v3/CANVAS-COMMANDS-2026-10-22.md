# 画布正式命令与保存恢复 · 2026-10-22

本批接续完整 v3 目标，完成本地画布的命令、持久回执、版本冲突与历史组闭环。基线 HEAD `9795d40616d59801300bb1b4c042db441d2866f8`，保留已有 H0 与账户/订阅 WIP。未提交、推送、生产迁移、部署或发布客户端。不能将此批等同于 H0、G3 或 v3 全部完成。

## 用户可见变化

- 批量放入照片、锁定/解锁按整次操作保存和撤销，最多 300 项；失败不留下部分修改。
- 保存结果不明时提示“确认上次操作”，暂停同画布新编辑。刷新或重启后仍可确认，不会重复放图、便签或移动。
- 画布被其他写入更新后，当前页面会明确提示、刷新内容并保留未提交文字；用户再次点击才执行，不自动覆盖。
- 冲突提示放在工具栏下方，便签编辑区出现时仍完整可见；画布按剩余高度伸缩，避免提示被底部裁切。
- 画布评论现在能够正确保存，也可跟随撤销/重做恢复。
- 采纳任务画布由正式命令记录，拒绝运行中、过期或其他项目任务。可评审/已完成且基线有效的草案采纳后进入人工编辑状态；确认弹窗说明采纳不可撤销。

## 实现边界

1. 新 `canvas_execute` 是唯一注册的本地画布 mutation IPC；创建、节点、评论、Undo/Redo、采纳均走此入口。旧无版本 IPC 已移除；Store 内部兼容函数不向生产前端开放。
2. 身份由可信 Rust `CommandContext` 构造，不能通过 JSON 自报。项目活跃、Local Authority、Board scope、冻结、task owner 与 baseRevision 均在写事务内重验。
3. 完整请求 ID/键/内容必须一致才重放；不同请求复用 opId 拒绝。重放使用原历史回执，不使用当前投影冒充旧结果。
4. 一次命令中的领域修改、历史组、Board revision、不可变审计和操作身份同事务提交，回执失败时整笔回滚。Board 每次生效命令只推进一次版本，评论也计入。已有项目选片历史/偏好证据不被画布记录污染。
5. `canvas_command_events` 与 `canvas_operation_ids` 由触发器禁止更新/删除。私有撤销栈单独维护，批量逆序撤销、正序重做，任一节点冲突整批回滚；新编辑使旧 redo 分支失效而不删历史。
6. `canvas_snapshot` 同事务读取版本、节点、评论和合法缓存路径。客户端 outbox 发送前落盘；确认前验证回执身份、版本及每个操作的结果结构，格式损坏也保留原请求。
7. TypeScript/Rust 共用 15 类协议样例。正式协议将目标包的设计样例扩展为 `action:{type,data}`，复用既有 DTO；设计及取舍见 [ADR 0045](../ADR/0045-canvas-commands-and-durable-confirmation.md)。

## 迁移与回退

新增 SQLite 0029，未修改历史迁移。旧 history rowid、undone/redone、评论正文保留，旧评论默认可见。升级前仍由 Store 自动备份并检查完整性。

回归测试建立真实 v28 临时库，保存非连续 rowid 及不同历史状态，升级后逐项核对；以只读连接打开自动备份，确认原历史和 v28 registry 保留，foreign_key_check 为空。仅操作新临时目录，未打开用户资料库或生产库。

若将来回退旧程序，须恢复对应升级前备份，不能让旧程序直接打开 v29 库。此文档不是对生产执行迁移的授权。
