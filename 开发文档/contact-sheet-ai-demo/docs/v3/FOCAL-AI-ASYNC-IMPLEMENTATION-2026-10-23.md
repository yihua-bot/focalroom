# Focal AI 异步图片链路：本地修复与交接

2026-10-23。来源：HEAD 9a00be8 加共享工作树。保留外部的 0021、迁移登记及上游 300 秒配置；不覆盖其他文档。不修改已报告生产使用的迁移字节。

## 修复内容

1. 控制器仍用现有 NestJS 分发入口，异步逻辑移入 HostedAiService。原 500 存在可以从代码确认的原因：INSERT 漏 body_hash/policy、RUNNING/FAILED 不合法、结算占位符与参数不匹配。不能归因为必须改用另一套装饰器。
2. 同步/异步共享输入、图片授权、策略、账户额度预留和严格计量校验；删除直接读环境变量并绕过这些边界的 fetch。异步结果与账本原子写入，未知失败不退款。
3. 客户端托管图片请求已接入提交与只读轮询。提交回执丢失按原编号查询，不重发图片；错误任务 ID、不可信 pollUrl、撤销登录和 UNKNOWN 不得绕过。文字仍沿用原同步路径。
4. 完成结果可恢复读取 24 小时，过期清正文，计量与摘要保留；详见 ADR0046。此为本地代码行为，不说明线上版本已一致。
5. 两个旧测试的迁移白名单遗漏 0020/0021，已同步实际登记，补核新增结果列；没有删除断言、放宽状态约束或运行生产 DDL。

## 给客户端压缩实现的约定

可以并行修改 AI 派生图准备层；本轮已修改 `agent/openai.rs`、`agent/openai/hosted_async.rs` 和 `tests/hosted_ai.rs`，请避免覆盖。

- 保留 store:false、现有策略/请求编号和图片同意标头。客户端 requestId 即 jobId，不能每次轮询或重连换一个编号。
- 提交体还是现有 Responses 格式；返回 `{jobId,state,pollUrl,result,error}`。只在 COMPLETED 且无错误、真实完整结果可用时继续解析观察。
- 不需要恢复旧 focal_chat 直连。统一 Agent 的图片请求已经通过 OpenAiProvider 自动走异步。
- 不改原片、普通显示缓存或正式调色渲染。需要压缩时生成独立的 AI 派生图，按 base64 和 JSON 之后的**整份请求大小**控制；“512px”本身不保证低于 500KB。
- 概览与细节比较的要求不同。改变观察图尺寸/质量必须记录真实输入并更新相应缓存身份，不能将更低质量结果当作旧高质量观察，也不能把元数据当看过图片。
- 本轮没有实施统一 512px 压缩，没有证明生产断连来自上传大小。先对照 API 直达、Nginx 和 Tunnel 的同编号请求日志定位，不凭客户端 bytesWritten/bytesRead 确认某层拒绝。

本轮测试使用隔离 PostgreSQL、回环 HTTP 和固定模型夹具；零生产 API、零真实图像上传、零真实模型费用。

- Rust 定向：agent_vision 46 项、hosted_ai 7 项通过，共 53 项。含正常异步、提交回执丢失、只读查询连接失败、错误任务 ID、UNKNOWN、会话撤销以及原有直接视觉链路。不是 Rust 全量结果。
- 严格 Clippy（all-targets + integration-harness）、fmt、typecheck、lint 已通过；末次结果与日志摘要见 evidence 清单。
- 云端全套使用每套独立数据库：最终 13 套、96 项通过、0 失败，其中异步专项 8 项。首次失败为两个陈旧迁移清单断言，修复后全套通过；随后增加同 UUID 跨账户结算和结果过期回归，再执行最终全套。原始日志与源码摘要见 `evidence/focal-ai-async-2026-10-23/verification.json`。
