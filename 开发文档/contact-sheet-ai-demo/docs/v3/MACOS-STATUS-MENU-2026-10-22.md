# macOS 菜单栏图标补齐

日期：2026-10-22。

## 问题与实现

原客户端仅在 `tauri.conf.json` 配置安装包、Dock 图标，没有初始化 macOS 状态栏图标，因此应用启动后顶部右侧没有 FocalRoom 入口。

新增 `src-tauri/src/macos_menu.rs`，在 macOS 应用启动时创建受 Tauri 管理的状态栏图标和两个菜单项：

- 打开 FocalRoom：显示应用、取消主窗口最小化、显示并聚焦主窗口。
- 退出 FocalRoom：沿用正常应用退出入口。

复用 `public/focalroom-mark.png` 的透明轮廓，生成 44×44 模板图，由 macOS 适配菜单栏深浅色外观。没有重新绘制品牌或附加文字。仅为 macOS 开启现有 Tauri 的 `tray-icon` 功能，无依赖版本升级。前端语言变化经独立原生命令更新菜单，支持中文、英文、日文、韩文；浏览器端不调用该命令，其他桌面平台返回无操作成功。

实现集中在单一原生模块，复用品牌与现有语言状态，不增加一套设置或项目写入通道。

## 原生检查

构建并启动独立的 `FocalRoom Menu Review.app`，实际 bundle identifier 为 `studio.focalroom.statusmenu20261022`，与正式客户端数据目录隔离。启动后显示项目列表和内置 12 张照片的演示项目。产物为约 66.85 MiB 的 debug、ad-hoc 签名检查包，不作为正式分发包。

CUA 可读取主窗口及应用菜单，但访问 SystemUIServer、ControlCenter 均返回 `timeoutReached`，无法直接获取顶部右侧状态栏截图。未把这个工具限制包装成自动化验收通过。

用户已对正在运行的独立检查版实际确认：**「图标可见，菜单正常」**。该反馈覆盖图标可见和菜单显示；四种语言逐一切换、窗口最小化后的菜单唤回、退出进程和浅色/深色外观逐项截图未单独记录，不扩张该反馈的验收范围。
