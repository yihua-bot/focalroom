# Focal AI v2 — Unified Photography Agent 实施与验收

> 2026-10-23 接续：S2/S4 本地工程增量已实现，当前状态与明确边界见 [创作上下文与跨轮修订](FOCAL-AI-CONTEXT-ITERATION-2026-10-23.md) 和 [当前回归报告](FOCAL-AI-CONTEXT-TEST-REPORT-2026-10-23.md)。本文下方 S1 限制及 S2–S5 待办为此前分阶段计划；其中上下文读取、独立分支、原创方法检索、经确认项目偏好已由增量覆盖，真实模型质量、完整 v3.1 和发行未因此完成。

## 1. 产品目标与本轮边界

最高研发优先级：把 Focal AI 连接为嵌入摄影工作台的统一助手。摄影知识讨论、影像分析和草案操作共享一个入口，不要求摄影师判断“聊天模式”或“任务模式”。沿用现有 AgentEngine、PolicyGate、预算、视觉观察、作者记忆及画布草案机制，不新建另一套编排器，不拆分多 Agent。

**本轮交付 S1：统一会话及现有工具循环的端到端连接。S1 完成不等于整个 Focal AI v2 完成，更不等于真实摄影质量验收完成。** 本轮没有发布生产 API、更新官网或发行安装包。

代码起点为 `d24616c`；联调期间另一会话推进了 `a140fea` 并留下画布审稿功能改动。保留这些改动，验证基线以测试报告记录的文件摘要为准，不把第三方提交当成本轮提交。

## 2. 已核对的旧问题

- 旧 `focal_chat.rs` 直接调用托管 Responses 服务，绕过现有 Agent Runtime；`FocalChat.tsx` 负责另一套聊天请求。
- `AIPanel.tsx` 让用户切换“对话 / 选片任务”，模型仅通过建议标记或关键词引导跳转。
- SQLite 聊天历史仅按项目归档，没有账户归属，不能安全地自动发送给另一个登录账户。
- 旧普通聊天最多附六张图片，跟引擎的检索、视觉授权、缓存、工具回执、草案流程不连续。
- `d24616c` 已有 `store:false` 及附图授权标头；这两项不能再描述为该版本仍缺失的协议修复。

## 3. S1 已实现

### 3.1 单一入口与执行路径

```text
AIPanel 单一输入框
  → StartConversation（明确范围、焦点、登录账户、图像授权与上限）
  → AgentEngine.request + 持久回执 + 冻结服务身份
  → ContextBuilder
  → 模型直接回答，或调用受限摄影工具
  → 回执持久化 → 下一轮判断
  → 回答 / 追问 / 真实选片草案 / 独立画布草案
  → GUI 展示 → 人工采纳
```

普通问题可以用 NoAction 返回自然回答；不要求为了知识交流先调用工具。没有照片的项目也能讨论摄影。旧 StartTask / StartCanvasTask 继续兼容历史任务；新界面统一发送 StartConversation。旧 `focal_chat` / history / clear IPC 已撤销注册，不再保留另一条可调用的推理路径。

新增的任务类型在本地可用项目中授权现有选片和画布**草案**工具。模型先获得查询、观察和创建草案的工具；真实草案创建成功后，再提供对应编辑与送审工具，避免每一轮都携带全部画布定义。可见工具的展开不增加冻结授权。模型没有 ApplyDraft 或正式画布写入工具；用户文字不能扩大正式写入权限。共享、迁移中的项目沿用权威边界，不因新会话获得本地画布写入权。

### 3.2 摄影上下文

- 项目简介、当前及任务基线版本、用户目标、当前照片焦点与可访问范围。
- 现有项目记忆及被现有规则允许的作者记忆，按需检索，不把聊天记录当长期审美偏好。
- 提供画布来源时，冻结画布版本与选区，通过既有 get_board 查看；操作发生在独立草案中。
- 照片列表、现有序列、检索、视觉观察、比较等沿用既有工具及成功回执。
- 本轮历史、追问和答复，以及同一项目中可复用的近期已完成或已送审会话。暂停中的跨轮目标衔接仍需 S2 补齐。

范围与焦点分开：例如项目范围有 300 张照片，摄影师当前指着两张讨论；模型可知道这两张是焦点，不再只能看到全项目的一串文件名。焦点必须属于本次范围。画布来源包含范围外照片时拒绝，不自动扩大范围。

**仍有限制**：需要从画布发起或传入有效来源才有当前画布上下文；尚未提供任意画布浏览、全部操作历史、外部调色版本、出版版式的统一检索工具。

### 3.3 历史、隔离与恢复

不新增数据库迁移。复用 task_messages、agent_steps、agent_checkpoints 和 agent_task_grants。

- `conversation_context` 保存由后端生成的会话上下文快照和版本指纹。
- 会话绑定真实服务身份及账户；前端的 expectedAccountId 仅用于发现登录状态变化，不能决定真实身份。正式请求由 AgentEngine/CloudAuth 绑定。
- 复用历史必须同时满足：同项目、同账户、同冻结服务身份，且旧照片范围仍被本次范围覆盖。
- 历史最多 24 条、12,000 字符；当前轮追问记录也有界。发送前依据本次上下文上限进一步裁剪较旧历史，为运行时信息留出空间，记录 omitted_messages。持久原记录不删改。
- 历史及项目数据作为不可信数据提供，不进入系统指令，不增加权限。
- 检查点加入 conversationBinding，恢复时验证；旧任务没有绑定时仍走原路径。
- 成功回答、追问、用户答复、草案摘要跟执行事务一同保存；结束审核不覆盖已保存的回答。
- 旧 focal_chat_messages 表保留。由于无法证明账户归属，不自动迁入新账户历史，也不自动转发给模型。
- 正式客户端的任务投影按真实账户过滤，退出不显示其他账户会话；控制任务同样验证冻结账户身份。

### 3.4 GUI 反馈

- 移除“对话 / 选片任务”切换和建议标记跳转。
- 一个输入框表达摄影问题或创作委托；张数仅作为可展开的参考选项。
- 显示实际持久阶段和真实等待时间；保留暂停、恢复、取消、结果不明保护。工作循环意外退出时保存失败状态并通知界面，不自动重试，避免一直停留在“执行中”。
- 回答、追问和用户答复形成连续消息；不再漏掉模型的普通文字回答。
- “已查看 N 张照片”仅来自成功的 vision_observed 工具回执。可展开事实、解释、不确定性，并定位照片；元数据检索不显示为视觉观察。
- 选片及画布卡片绑定真实草案 ID，可打开审核。原作品保持由用户确认后修改。
- 新增文案同步中、英、日、韩。原生生产包不包含浏览器验收使用的固定剧本 Provider。

## 5. 接续开发顺序

### S2 — 完整创作上下文与操作能力（P0，未完成）

1. 增加有范围约束的只读上下文工具：可见画布目录、作品及画布历史、外部编辑 Variant / Rendition、出版物当前版式。
2. 工具输出保留项目、版本、照片及观察来源；明确哪些是视觉证据、用户决定或模型假设。
3. 支持从上一轮草案生成下一份独立修改方案；保留父草案和版本关系，不通过新任务直接修改旧任务草案。
4. 画布反馈卡片显示具体变动和影响范围；正式采纳走 CommandHandler，并验证并发与锁定对象。
5. 长任务可观察、可中断、可恢复；未知传输结果不能当作零花费重新运行。

**完成标准**：从同一段对话提出一个真实创作问题，模型能按需检查相关项目状态；用户修改目标后能得到有来源的新方案，原版不变，所有操作在界面可检查。仅把对象摘要拼到提示词不算完成。

### S3 — 300 图创作旅程与专业评测（P0，未完成）

固定验收目标：300 张有授权的摄影素材，要求找出三条不同创作线索，各选 20 张，生成三份独立画布方案。

工程门槛：

- 三份真实草案各有 20 张范围内有效照片，关联真实节点与解释，不是三段聊天文本。
- 每项视觉判断能追溯成功的观察；精确记录实际看过、缓存命中和未观察的范围。
- 用户指出一条建议不对后，产生新的方案和理由，不能覆盖原版。
- 原图哈希、正式项目版本在采纳前不变；取消、重启、服务错误、账户变化、预算边界均有检查。
- 记录完成率、错误、延迟、实际计量、用户采纳及修改，而非只判断 HTTP 成功。

当前单次图像上限仍为 100 次，图库范围上限 500 张。300 张可作为候选范围，**这不代表已经观察全部 300 张**。需要明确增量观察/缓存策略和用户可理解的额度控制，再验证大项目；禁止为通过测试悄悄放大预算。

质量门槛：真实摄影师盲评视觉事实、叙事区分、编辑理由、可用性；保留原计划 ≥30 任务、≥10 摄影师要求。回环模型夹具、生成色块、自动评分均不能替代这项验收。

### S4 — 可纠正的审美记忆与摄影知识（P1，未完成）

- 用户明确确认后才把偏好沉淀为项目或个人记忆，带证据、时间、范围、反例及撤销入口。
- 区分一次性选片理由、项目目标和长期偏好；用户否定后能更正、停用并使旧上下文失效。
- 有来源、授权和版本的摄影知识检索；摄影史、摄影书和引用不得依靠模型编造来源。
- 依据真实评测分别选择编排与视觉能力；服务切换仍需要独立授权，不自动跨供应商回退。

### S5 — 生产候选与发行（P0，上线前执行，未完成）

- 使用隔离评审账户完成托管网关、账户额度、连续会话和真实图片小范围验证，再做 300 图旅程。
- 真实调用须遵守用户授权和生产操作批准；本轮未重传用户照片、未调用付费模型。
- 双端登录切换、离线/联网、异常余额和恢复测试；不能把开发机配置当用户可用服务。
- 固定源码版本、CI、候选签名/公证/更新和生产部署核对；旧版发行记录不能代替新候选。
- 四语生产文案检查和用户操作说明更新。公开宣传必须与已验收能力一致。
