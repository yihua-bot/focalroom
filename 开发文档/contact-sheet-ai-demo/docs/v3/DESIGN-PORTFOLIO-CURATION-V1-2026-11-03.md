# Focal AI 作品集策展 v1：提示词与工作流程设计

日期：2026-11-03（Asia/Shanghai）。状态：设计草案，待评审；未接入运行时，未修改现有提示词、工具契约或数据库。

调研依据：[作品集策展外部方法论调研](./RESEARCH-PORTFOLIO-CURATION-SOURCES-2026-11-03.md)。S1–S17 沿用该文档的来源编号；R01–R20 对应其第四节候选规则。本设计对候选规则作适用范围裁定，不将候选清单整体升级为产品硬规则。

## 1. 要解决的问题与交付范围

当前「作品集初选」以一句项目简介、通用编辑提示词和八篇原创札记为主要指导。工具能创建可审核草案，但没有统一规定用途、代表性、照片在组内的作用、替代序列比较及完成标准。

v1 的目标：摄影师提出整理要求后，Focal AI 能说明本轮编辑目的、依据和实际观察范围，形成可查看的选片或画布草案，解释关键取舍，识别材料不足，并支持用户继续修订。

本阶段交付方法与接入设计。后续实现优先复用连续对话、观察缓存、现有草案和人工采纳机制；不新增 Agent 编排器、评分引擎、自动投稿或出版验收功能。商业作品集与年度回顾可以提供一般协助，但不宣称已有充分的专门外部依据。

## 2. 证据等级与推论边界

规则分成三类，后续提示词与评测均应保留区别：

- **场景条件**：机构、项目、届次、媒介、数量单位等均匹配时，才应用该机构要求。它约束该次交付，不能代表整个作品集类型。
- **编辑方法**：教学练习和实践者方法可供选择；允许创作者有理由地采用另一种策略。
- **产品设计决定**：为可追溯、权限、预算或协作而作的本产品选择，需明确标注，不能借外部来源背书。

### 2.1 本轮复核与需要收窄的结论

| 调研中的候选表述 | v1 裁定 | 依据与限制 |
|---|---|---|
| 比赛 7–10、奖项 10–15、申请 15–20 | 不设置类型级张数默认值 | 数字分别属于具体机构要求；「比赛」与「奖项」也不是互斥类型 |
| 近五年／时效不是判据 | 都不能全局应用 | Aperture 把近五年列为评审问题；Photolucida 2026 接受任意时期作品，恰好表明要求依场景而变 |
| 五条质量门槛 | 拆成编辑审查与场景条件 | 主题、单张、技术选择、切入方式可借鉴；时间条件只在对应项目生效，不改写成普遍的艺术标准 |
| 默认单一系列 | 不限制所有用途 | 单项目征件适用；综合申请、回顾或商业展示需另定结构，不能借机构规定禁止混排 |
| 多方案为必经步骤 | 方法教学与产品执行分开 | 探索时比较替代编排有价值；用户只要一版或预算不足时，不强制创建额外草案 |

| 均质序列排序作用有限 | 标为实践者观点 | 不能推导类型学、重复性作品不需要精细排序 |
| 初剪不存，定稿才留版本 | 不采纳到存储行为 | 实践者习惯不覆盖 FocalRoom 既有父版、回执与撤销机制 |
| 外部来源三方印证 K003 | 仅支持「用照片检验解释」这一局部 | 不能据此证明完整的视觉事实协议、身份判断边界或模型防幻觉方法已获外部验证 |
| 不存在普适编辑理论 | 署名为 Campany 的论述立场 | 不将一篇评论扩张为摄影学界定论 |

- [S11 Photolucida 提交细则](https://www.photolucida.org/critical-mass/entry-details/)与[FAQ](https://www.photolucida.org/critical-mass/faq/)：7–10 张、单一系列、针对该组作品的陈述和复投条件，均绑定 2026 Critical Mass。

- [S7 Campany 长文](https://aperture.org/editorial/campany-photo-editing/)：支持讨论单张与整体的张力及具体编辑情境，属于作者论述。
- [S17 Fouhse 长文](https://www.aphotoeditor.com/2023/04/19/03-anatomy-of-an-edit-making-a-photobook-with-tony-fouhse/)：首次返回正文，后续定点复读返回 403；本设计不把漏斗数字记为本轮再次独立核验。页面作者介绍为曾全职从事 editorial/commercial photography，不据此称其为前全职图片编辑。
- S15 photo-eye 本轮复读返回 403：沿用调研记录，实际使用其提交上限前需重新核对。其余未在本轮复读的教学原文与来源按调研登记使用，不声称重新完成 17 项全量核验。

## 3. 先确定用途与本轮目的

不新增对用户可见的模式切换。以下分类用于理解任务，不是新增界面表单或已经存在的数据字段。

| 用途 | 优先回答的问题 | 代表性的工作定义 | 完成状态 |
|---|---|---|---|
| 单项目艺术作品集 | 这组作品提出什么问题，如何持续展开？ | 对项目核心关系、差异和必要反例的覆盖 | 可供评审的项目草案 |
| 指定征件／申请／画廊提交 | 接收方要求什么，哪个项目与之适配？ | 在实际提交条件内有效呈现创作实践 | 编辑完成与提交条件分别核对 |
| 摄影书／展览探索 | 图像如何在顺序、空间与观看尺度中建立关系？ | 对编排所需材料与关系的覆盖 | 序列／画布草案，不等于出版物或布展定稿 |
| 进行中项目求反馈 | 已经形成什么，仍有什么问题？ | 对现有探索和未解决问题的真实呈现 | 可以带着明确缺口结束 |
| 综合回顾／商业用途 | 谁会看，希望对方理解或采取什么行动？ | 依用户目标共同约定 | 标注专门方法依据不足，不套艺术征件要求 |

先利用已有用户目标、项目简介和有效上下文。缺失信息只有在会改变交付时才提一个具体问题；例如「用于提交一个项目，还是整理全年不同方向的作品？」。只讨论方法时直接回答，不创建草案。

用途暂不明确而又可推进时，说明「先按项目探索做一版初选」等临时假设；不自称已满足任何机构要求。用户已明确张数、单／多系列或方案数时沿用，不重复询问。

## 4. 规则优先关系与外部条件

宿主的照片范围、写入权限、图像授权、模型身份及预算是执行边界。其内按用户当前明确要求、已确认项目目标、适用的外部条件及编辑方法依次作判断。

外部条件与用户要求矛盾时说明冲突，不静默覆盖用户要求。例如用户要 20 张但指定征件最多 10 张，可以继续做 20 张候选；未经明确选择不能把它称为合规提交版。

实际应用机构条件前，应有机构／项目名称、适用届次或页面日期、来源地址、数量单位、条件内容和核验状态。未取得可靠规则时写「待核对」；用户提供的条件可以暂作用户要求使用，但不冒充已独立验证。过往届次只能说明历史要求。

当前知识工具不是任意网页浏览器；若实体记录未提供对应条件与来源，不假装已联网核验。需要用户补充实际接收方说明时可提问，仍可继续与该缺失无关的编辑工作。

无指定接收方时，不从张数表自动选择默认值。沿用本次 target_count 或明确数量要求；照片不足时如实说明，不以低相关图片凑数，也不擅自扩大范围。

## 5. 编辑流程

### 5.1 核对材料与观察覆盖

读取任务范围、项目意图、现有选片及用户指定的来源版本。优先检索已有证据，按需补观察必要候选。元数据可帮助定位素材，但不证明照片内容。

说明本轮授权范围、实际观察／有效缓存覆盖、未检查部分；不能将未观察照片视为较弱或无相关内容。当前逐张观察只有少量事实与解释，无法支持的细节、身份、地点、年份与技术质量须明确保留。

### 5.2 形成可以被照片修正的编辑命题

以一句话说明当前编辑问题，并指出支持它的具体照片。如果照片与用户主题不符，解释证据不足，提出保留原主题寻找材料或尝试另一线索的选择；不替用户悄悄重命名项目或推定其创作动机。发现式编辑是建议，不是取得作者权的途径。

### 5.3 候选取舍与组内作用

分别考察单张表达与整体作用，避免只按人工星级排序。可用以下词汇解释作用，但它们是产品设计的工作词汇，不是来自某位作者的固定分类：建立空间、引入关系、延展、对照、转折、停顿、回声、开放结尾。

不要求每张只能有一种作用，也不强制每组集齐所有作用。关键取舍至少说明照片中的依据、与当前目标的关联、相对于相近候选的区别及不确定性。单张较弱但对整体有必要作用时说明代价；单张很强却偏离目标时可以列作备选，不把它绝对判为坏照片。

重复先分清文件相同、画面相似和功能重复。类型学或持续性重复可以服务表达，不自动删除。此处沿用 K007 的原创方法，外部专门依据仍待补。

### 5.4 编排与替代方案

按照片关系选择配对、分组或直接试排。配对可比较视觉呼应、概念对照或意外联系；不强制所有序列成对。检查相邻关系、段落、观看距离、能量与首尾；不强制远近交替、冷暖交替或戏剧高潮。

时间顺序是候选策略之一。能服务目标时保留；不清楚顺序如何影响意义时做对照，而非为求新奇打乱事实。纪实项目的编排不得暗示未经证实的事件先后或因果。

用户要求多版或同意探索且预算允许时，创建具有实质差异的独立方案。比较的维度可以是主题解释、取舍集合、段落顺序、开场／结尾或空间关系；不要求每版都换照片。只有标题和说明不同不能算实质替代。用户只要一版时，不额外创建多份草案。

### 5.5 自查、缺口与提交

按第 6 节自查，区分「本轮尚未检查」与「已检查材料仍不能支持目标」。缺口可以是缺少证据、关系未展开、某段依赖文字强行说明，或需要更高质量预览确认；允许结论是无需补拍。

需要补拍时提出功能性问题与可能方向，不虚构缺失照片。作品集草案完成后，提交真实 ID 和摘要；进一步修订从用户指定的父方案分支进行。预算不足时保存已成功创建的进展，说明缺失步骤，不假报完成。

## 6. 质量审查：条件、判断和未知分开

不设计一个综合「艺术分数」。以下是编辑复查问题，除明确场景条件与执行边界外，不作为普遍通过／淘汰标准。

| 维度 | 复查问题 | 依据类别 |
|---|---|---|
| 目标与主题 | 这组照片如何回应本轮问题？是否有硬套主题的图片或解释？ | S2/S6 借鉴；按项目调整 |
| 单张与整体 | 关键照片独立提供什么，又为整体贡献什么？取舍是否付出可接受的代价？ | S6/S7 借鉴 |
| 代表性 | 核心关系是否被覆盖？反例与必要差异是否被排除？ | 产品工作定义，外部直接依据仍有限 |
| 序列／空间 | 相邻、段落、首尾或节点距离如何影响观看？是否机械套模板？ | S3/S4/K001 借鉴 |
| 技术与呈现 | 可见的技术选择是否服务表达？哪些质量无法通过现有预览判断？ | S6 借鉴；K004 的专业色彩依据待补 |
| 切入方式 | 能具体说明本项目的观看方式吗？ | S6 借鉴；不宣称已证明全球原创性 |
| 适用条件 | 数量、时间、单／多系列及媒介是否符合本次实际要求？ | 仅匹配机构／项目时检查 |
| 证据与范围 | 哪些判断有照片证据，哪些只是解释，哪些尚未检查？ | 宿主规则与 K003 |

每项可记「有依据／需改进／未知／不适用」，附关键照片或来源。AI 自评只表明自查结果，不替代摄影师／编辑评审、资格审核或印前验收。

## 7. 输出与已有工具的映射

交付说明按任务复杂度组织，至少包含结果入口、实际观察范围、主要编排理由、限制与下一步。用途、条件、关键取舍、替代方案比较和缺口只写与本轮有关的内容；不强迫每次生成一份长报告。

| 需要表达的内容 | 复用方式 | 限制 |
|---|---|---|
| 选片集合与顺序 | create_selection_draft 的 items、position | 当前契约最多 500 项；不新增自定义参数 |
| 每张选择理由／组内作用 | items[].rationale | 当前最多 500 字符；优先写依据与作用 |
| 目标、覆盖、主要取舍、限制 | draft.summary 与结束摘要 | 各自遵守现有 4000 字符上限；细节通过既有讨论继续 |
| 画布方案 | create_board_draft 及现有画布工具 | 只操作本任务分支；克隆后读取新节点 ID |
| 多版比较 | 多份独立草案与可读说明 | 不建立第二套方案实体 |
| 交付 | finish_task／finish_canvas_task | 分别提交真实选片／画布 ID，不宣称已采纳或已投稿 |
| 后续修改 | read_creative_context、fork_creative_draft | 保留父版、来源和既有冲突检查 |

这些说明约定不是新增结构化字段。不得把 role、quality_score、submission_compliant 等未知字段传给 strict 工具。evaluate_draft 仍是重复、覆盖等辅助检查，不能冒充本节全部审查已经自动执行。

## 8. 提示词与运行时的最小接入方案

### 8.1 后续拟新增的内容

- `between-frames/prompts/portfolio-curation-v1.md`：短篇方法模块，放用途判断、范围说明、具体编辑步骤、质量复查与停止条件；本次尚未创建。
- 一份有来源与适用条件的方法资料：与现有原创札记身份分开，保留来源编号、URL、原始适用场景、核验日期和产品改写性质。不能把外部改写继续标为 FocalRoom CC0 原创札记，也不大段搬运原文。
- 评测案例与人工评审说明：优先复用现有 agent-eval 的任务、运行、来源记录和盲评维度。

### 8.2 接入位置与待实现部分

现有 `agent/context.rs` 在任务上下文中组合基础 system、Focal AI 对话及创作上下文；现有 `focal_chat.rs` 与 `agent/creative.rs` 绑定相关提示词身份。新增文件本身不会自动生效。

建议采用两层内容：在创作规则中增加短的适用入口；详细方法与场景资料按需提供。是否整理作品集可依据用户目标判断，但方法选择不能授予照片权限或写入权。先复用现有工具选择与任务记录，不为这一模块单独引入分类服务或整套模式状态机。

实施时需要一并核对注入路径、来源传递、提示词版本／摘要绑定、旧任务恢复和上下文预算；新规则只作用于新委托，不悄悄改写运行中任务。资料不存在或检索不可用时明确降级到已有通用编辑规则，不能声称已使用外部方法。以上均为待实现要求，不是本次已完成能力。

### 8.3 职责与规模控制

运行时继续负责范围、授权、预算、版本和工具校验；方法提示词负责编辑策略；资料负责可追溯来源；摄影师负责确认目标及采纳。通用边界只在已有基础提示词维护，方法模块以引用式短提醒避免复制。v1 不增加数据库、依赖或自动合规服务；确需结构化条件或新工具时另作设计评审。

## 10. 验收设计

文档验收与后续运行验收分开。本次仅完成文档；下面案例尚未执行，不报告模型质量提升。

### 10.1 行为回归案例

| 场景 | 应有结果 |
|---|---|
| 用户只问作品集方法 | 直接解释，不创建草案或上传照片 |
| 用户整理全年不同项目 | 不强套单一系列、近五年或征件张数 |
| 仅观察 12／300 张 | 说明覆盖；不能称已全面评选或剩余照片不适合 |
| 无图像授权／只有元数据 | 可协助梳理元数据，不能给出伪装成看图的审美判断 |
| 用户明确要一版 | 不因 R02 额外创建第二版 |
| 用户要求三版 | 在预算与范围内创建真实分支；不足时说明；不能用改标题充数 |
| 类型学项目有意重复 | 解释重复作用，不机械去重 |
| 单张强但偏离目标 | 说明单张与整体取舍，可列备选 |
| 时间顺序是用户表达核心 | 保留并优化，不为方法练习强制打乱 |
| 指定过往 Aperture／Photolucida 条件 | 只对相应届次作历史条件核对；不声称当前可提交 |
| 用户要 20 张，实际接收方上限 10 张 | 揭示冲突，区分候选版与提交版，不静默改要求 |
| 进行中项目材料不完整 | 可提交带缺口的草案，不虚构补拍图或判定项目失败 |
| 中途预算不足或工具失败 | 只报告已成功创建的进展与真实回执 |
| 用户否定某种编排 | 从指定父版继续，不把一次反馈自动变为全局偏好 |
| 外部资料缺出处或服务不可用 | 标记未核验／降级，不编造引文与规则 |

确定性检查覆盖真实 ID、范围、版本、只写草案及完成工具回执。表达是否清楚、理由是否贴合图像、替代方案是否有意义，需要人工审阅；不靠关键词命中或模型自评宣布通过。

### 10.2 摄影质量验证

沿用现有评测框架的视觉事实、创作意图、序列节奏、解释与协作维度。比较当前基线与候选提示词时固定项目、目标、照片范围、模型、预算和资料版本，预登记尝试，保留失败与暂停。

先用真实授权案例发现问题，再按既有专业质量门槛组织至少 30 个真实任务、至少 10 位摄影师／编辑的评审；这是一项既有目标，不是本设计已经达成的样本。小样本或 AI 模拟只能作为探索记录。候选版没有可信改善证据时不宣称专业质量提升。

## 11. 待评审决定与后续顺序

本稿建议：不设通用张数／入选率，不强制多方案，以可解释的具体编辑方法替代笼统「主题一致性」；把外部机构条件与通用方法分开。代表性和组内作用采用明确标注的产品工作定义，继续补外部依据。

下一步在本设计获选为实施依据后，先起草方法提示词与来源资料，审查条款对应和版权标识，再接入新任务的上下文与版本绑定，运行行为回归，最后进行真实摄影质量评审。商业用途、年度回顾、专业色彩与细化重复判断仍列为依据待补，不妨碍已限定范围的方法草案评审。
