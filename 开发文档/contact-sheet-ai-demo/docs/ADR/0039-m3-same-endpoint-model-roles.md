# ADR 0039：同一端点的图像观察与策展模型分工

日期：2026-10-17。阶段：M3 功能增量，整体仍 partial。

## 问题

运行时原先只实例化一个 Responses 模型，主循环、图像观察、能力、授权显示与缓存检索都引用同一型号。直接增加观察型号会导致授权指向错误、恢复时混用配置，以及检索仍按策展型号过滤观察缓存。

## 决策

保留现有策展主循环和视觉工具接口，分别冻结两个 OpenAiProvider 实例。默认复用同一实例；可信部署可配置独立观察型号。两者必须使用同一适配器和标准化端点摘要，不能借此新增跨服务传输或自动 fallback。

- 主循环沿用 AgentOrchestrate 路由，要求工具调用和遵循指令能力。图片只通过视觉工具发送给观察实例；基于工具事实的策展不伪装为主模型直接看过原图。
- 观察实例独立解析能力声明、按 VisionObserve 路由和自身费率执行。观察能力错误只阻止视觉请求，用户仍可将图像预算设为零继续文本编辑。不会改用具备视觉能力的策展实例代传图片。
- 两份能力文件分别绑定精确端点和型号；观察型号不同且没有观察能力文件时，只允许其精确内置配置，不能继承策展能力文件。显式观察文件错误时不回退内置配置。仅设置观察文件时，也按当前主型号校验，不能静默忽略。
- model_binding 增加可选 observation（型号、能力摘要），端点与 adapter 继承主身份。型号与有效能力相同时省略新字段，保持单模型身份序列化兼容。完整组合写入不可变绑定和检查点；任一角色或能力变化都要求新委托，密钥轮换不改变身份。
- 图像 consent 的收件人摘要只使用实际观察型号；改变策展型号且观察收件人不变时，新任务可继续使用该观察授权。改观察型号需新授权；显式引用其他型号同意的任务在任何 HTTP 前拒绝。已有全服务 deny 规则不变。
- photo_observations 的 model_id、视觉费率和预留账本使用观察实例；事实检索按绑定的观察型号过滤。更换策展型号的新任务可复用同一观察来源缓存，换观察型号不能误命中。视觉 Prompt 与缓存版本保持 m3-vision-2。
- model_attempt / vision_reserved 追加 modelRole 和 modelId，复用现有任务累计预算、上传配额与结算账本。未知传输保留预留，恢复不自动重传。
- 主 Prompt 变更为 m3-openai-9，明确两种角色与事实来源；Mock 仍为 m2-mock-2。旧 Prompt 的已执行任务按既有版本门槛重新委托，不改写历史。

## 配置与兼容

新变量 BETWEEN_FRAMES_AI_OBSERVATION_MODEL 和 BETWEEN_FRAMES_AI_OBSERVATION_CAPABILITY_PROFILE 均属部署配置；创建实例后冻结，修改后重启。Base URL 与实际运行密钥沿用主配置，不增加前端任意端点/型号编辑入口。

AiConfig 增加 observation 只读投影，前端严格校验能力并显示实际观察收件人。未配置密钥时 observation=null，离线 Mock 流程保持原样。

没有迁移、运行依赖或原图库修改；内部标识保留 FocalRoom 的旧兼容命名。真实数据驻留、条款、账单和质量仍须独立核验，两个型号并不意味着更便宜或更专业。

## 验证与限制

本地 HTTP 用例覆盖两角色实际请求与可审核草案、端点拒绝、错误/隐式授权、观察缓存及检索、重开恢复/换型号与能力/密钥轮换、能力不足不回退、共享预算；环境配置与独立能力文件也有冻结/缺失/错配回归。UI 验证观察收件人、零图像编辑、禁止和严格投影。

最终计数、原始失败和复验日志见 V2-M3-MODEL-ROLES-TEST-REPORT.md。没有自动质量选模、全图库后台观察、独立跨服务 Adapter 或跨服务 fallback；专业评测与真人门槛不因此关闭。
