# ADR 0042 · 可信归档与独立空项目恢复

日期：2026-10-18。M4 运维增量，不扩展 M6/M7。

旧脚本引用不存在的 `../compose.yaml`，项目名只用于猜卷，不用于 Compose；恢复在切换目录后重新计算相对路径，忽略停 API 失败，并以 `pg_restore --clean` 覆盖现有库。数据库与预览也没有统一停写窗口，无法作为生产灾备能力。

采用两个薄 Bash 入口和一个 Python 3.11+ 标准库模块：共享定位、容器绑定、归档校验和错误处理；不引入新包、第三方备份镜像或新数据库 schema。Docker helper 复用实际 PostgreSQL 容器的镜像 ID，禁止拉取，网络禁用。实际挂载来自本项目 API 容器，避免猜错卷或 Docker 自动新建同名空卷。

同主机/用户/项目用文件锁排除并发运维，不自动删除锁文件；跨主机维护仍由管理员统一协调。

备份在维护停写窗口暂停全部当前运行的 API，PG custom dump 与磁盘预览一起校验；失败也恢复原进程状态，不隐式启动本来停止的副本。归档包含版本化清单和两个内容校验和，预览还逐文件核验内容寻址和数据库引用。临时文件不自动删除，归档以私有权限原子发布；不自动加密、不实现保留期清理。

恢复默认仅验证，真正写入必须显式指定/重复确认独立空目标；只支持相同 PG 主版本、私有磁盘预览。无覆盖模式，不执行 `--clean`。验证白名单成员、大小、普通文件、重复、路径/链接、校验和和预览引用后才接触目标。停写后再次查空，预览先恢复，PG 单事务恢复，最后核对表计数、迁移、对象与内容摘要。成功/失败都不自动启动目标 API，避免部分数据、过时会话或权限未经审阅即恢复服务。

操作员必须排除外部写入者并审阅实际部署配置；表计数前后相同不能证明没有外部并发更新。只处理受控可信备份，SHA256不等于认证，PG dump 可包含SQL。全局角色/最小权限、真实 R2、生产镜像与腾讯云灾备、健康检查、RPO/RTO、会话/授权复核均保持独立验收。

9项归档/故障边界、6类真实 Docker 演练、22表行内容摘要/2预览对象/非root读取核验与30项 API/PG回归见 [测试报告](../V2-M4-BACKUP-RESTORE-TEST-REPORT.md)。首轮恢复 helper 缺 `docker run -i`，已修并保留失败记录；不把哨兵 API 容器写成真实 NestJS 部署。
