# ADR 0034：模型特定能力声明与恢复边界

日期：2026-10-16。接续 ADR 0033，仅 M3；保留已有云协议与模拟评审工作，无新依赖、数据库迁移或线上操作。

## 问题

实际模型身份已绑定，但所有 Responses 端点/模型仍默认得到视觉、工具和结构化能力。相同模型名的任意代理因此可能被当成可用视觉模型；Router 也只检查一个主能力，不能保证观察请求的结构化输出与图像输入同时受支持。直接调用 Adapter 可以绕过 Router。

## 决策

1. **独立能力模块**：`agent/capabilities.rs` 负责有界配置解析、精确端点/模型匹配、版本和集合摘要。Provider 持有实例创建时的解析结果；Router 不读环境/磁盘，也不负责加载配置。
2. **默认拒绝未知模型**：内置精确目录仅包含已核对的 OpenAI 官方型号与本项目既有 DeepSeek 协议冒烟型号；代理/相似域名/其他别名不继承。自定义本地文件是可信部署声明，来源单列；无效显式配置不能退回内置目录，错误不回显路径/正文。
3. **声明不等于评测或权限**：仅支持现有 Adapter 实现的四项协议能力，不允许配置 embedding、质量、驻留、预算、授权。质量 `unmeasured`、驻留 `unknown`、原 consent/区域/预算门槛均保留。不能据内置来源推导摄影效果或服务承诺。
4. **组合要求共用**：Router 与 Adapter 复用所需能力规则，视觉请求同时要求视觉、结构化和指令能力。请求含图像时单独增加视觉要求，不能仅凭工具能力路由图片。直接 generate/observe 也在 HTTP 前检查。纯文本编排无需视觉，仍可执行已授权范围内的元数据工具。
5. **恢复绑定有效集合**：在既有 model_binding 和 checkpoint 中加入可选能力摘要。新实例摘要和旧绑定不同，或旧绑定无摘要，均在待处理工具执行前拒绝；密钥不参与摘要。旧结构可读取但不能补猜，保留原不可变账本。不修改 Prompt 文本，版本仍 `m3-openai-6`；视觉缓存键沿用 ADR 0033，不把声明变化等同观察内容变化。
6. **界面可操作**：IPC 暴露能力、来源、配置错误；委托面板阻止错误配置或不支持的图像请求，表单直接提交也检查。已打开授权卡遇配置失效时阻止继续授权，但仍能禁止图像。纯文本真实请求明确显示“不上传照片”，不再叫 Mock；密钥来源未知时显示部署配置，不猜环境变量。
7. **不提前做供应商回退**：现有单 Provider 与同提供方重试保持。真正跨供应商 fallback 仍须补供应商专属授权、独立 Adapter 和质量证据；本切片不以一个 allowlist 宣称 M3 路由完成。

## 原则与兼容

单一职责：能力加载与路由/网络分离；DRY：同一能力要求用于路由和 Adapter；KISS/YAGNI：只处理当前四种协议能力，不新增配置框架、迁移或动态探测。对旧任务明确要求重新委托，正式作品与人工偏好证据不变。`OpenAiConfig` 构造形状保留；测试通过显式可信 profile 注入，不以 localhost 放宽生产规则。
