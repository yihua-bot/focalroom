# ADR 0025：按需原图检视与精简 GUI 历史投影

后续修订：回执内部存储编码与 RAW 派生检视见 [ADR 0028](0028-m1-review-fixes.md)，历史回执对外语义保持首次结果。

日期：2026-10-15。状态：本地实现与本轮验收通过；M1 整体仍 partial。

## 问题

ADR 0024 的 100% 只针对最长边 1400px 的编辑预览。500 张图库中每次人工编辑又通过 IPC 返回完整历史前后状态，前端反复解析和保留大对象。不能以放大缓存代替原图，也不能通过删除审计或幂等回执降低内存。

## 决定

1. 原图由 `get_original_photo(projectId, photoId)` 按需读取。Rust 查询项目内的照片行，拒绝归档、跨项目或不存在的引用；前端不能传文件路径。点击实际像素缩放后，后端先核对文件与导入 SHA-256，再向 Tauri asset scope 授予该精确文件的只读访问，不开放原图父目录。
2. 本切片原图检视支持 JPEG / PNG，限制为 64 MiB / 3200 万像素，限制发生在浏览器解码前。其他格式、失联、文件内容变化和解码失败明确回退到缓存。原图不复制、不重编码；云视觉仍使用既有的授权 1400px 预览通道。
3. 原图 100% 定义为 1 图像像素对应 1 物理屏幕像素；CSS 尺寸除以 `devicePixelRatio`，窗口 resize 时更新。适合屏幕仍使用缓存。灯箱翻片/重连重建 viewport，迟到的异步响应不能覆盖已退出的检视。
4. `list_projects`、`get_project`、`execute_gui_command` 增加可选 `compact` 参数。桌面 GUI 显式请求精简投影：保留事件身份、类型、说明、时间及数量，不返回逐事件的前后状态和上下文。默认参数保持旧投影；数据库、CommandHandler 持久化幂等回执、Undo/Redo 和导出不变。精简操作只发生在事务提交后返回的副本上，不新增迁移。
5. 原图加载回调通过 Photo 的可选能力注入共用 viewport；预览仓库没有该能力，继续显示“100% 预览”。桌面仓库按照片复用回调，避免捕获完整项目快照和每次编辑重载原图。

## 验收与边界

3 项新 Rust 测试验证所属关系、指纹、格式/像素上限、失联、归档、原图不变，以及精简投影不改变完整审计和持久化重放。前端测试验证延迟读取、Retina 几何、失败回退和迟到响应；真实后端 GUI 使用 2400×1600 JPEG/PNG 区分原图与 1400px 缓存。

独立原生应用标识 `studio.betweenframes.m1inspection` 只使用新数据库。系统文件/文件夹选择、重复跳过、双图原图、保存、完整退出再启动通过；49 表内容和两张源图 hash 前后一致。详见 [验收报告](../V2-M1-INSPECTION-TEST-REPORT.md)。

asset 文件授权随应用进程结束失效；它不是云共享链接或可撤销协作授权。指纹校验针对请求时的文件，不能阻止其他程序在随后读取期间修改原图。色彩交由系统 WebView 解码/显示，不宣称已完成 ICC、HDR、16 位或校准显示器验收。精简 IPC 不解决 SQLite 完整历史与命令回执的存储增长，也不构成低端设备性能通过。
