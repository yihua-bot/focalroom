# ADR 0038：实际服务收件人绑定的图像授权

日期：2026-10-17。状态：采用，M3 增量；完整跨供应商 fallback 仍待实施。

## 问题

现有 OpenAI 兼容 Adapter 使用通用 provider_id=openai。图像授权也只保存 openai，因此切换实际端点或型号后，新任务可能沿用先前服务的项目授权。任务自身的 model_binding 能拒绝旧任务静默换服务，不能防止新任务借用旧授权。原生 IPC 和 harness 也不校验界面看到的服务是否仍是当前冻结实例。HTTP 自动重定向还可能转发图像请求到另一地址。

## 决策

1. 复用 ModelIdentity 生成版本化收件人标识：openai@SHA256(adapter、精确端点摘要、型号标识)。不含密钥、明文地址或照片；密钥轮换和既有尾斜杠规范化不改变收件人。能力摘要不作为收件人，仍由原 Router/Adapter 与任务绑定独立校验。
2. 复用 privacy_consents.provider TEXT 列保存收件人命名空间，无新迁移、依赖或配置框架。旧 openai 正向授权不推断来源、不升级、不生效；旧 deny 继续作为本项目全局图像禁止。保留历史记录与回执。
3. AiConfig.consentProvider 来自已冻结的实际实例。前端授权请求携带该不透明标识；AgentEngine.set_consent 在写入前校验实际收件人和视觉组合能力。原生 IPC/harness 共用同一方法；配置过时返回 CONSENT_TARGET_CHANGED，不能依照请求提供的地址重建服务。
4. 委托时校验显式授权属于项目且为新的收件人授权；绑定实际模型时进一步验证精确收件人，在任何模型 HTTP 请求前拒绝不匹配的显式授权。自动项目授权只查实际 model_binding 对应的收件人。视觉配额预留仍在同一写事务中重读有效权限，不借用其他端点/型号的授权。
5. 禁止云端图像会撤回本项目全部命名空间及旧授权；重新明确批准 A 只恢复 A，不复活 B。不同收件人的独立批准可以并存，供后续受控路由使用，但本轮不执行任何自动跨服务切换。
6. 图像授权回执继续持久幂等；冲突和落库故障回滚已有授权撤回。前端通信重试保持同 requestId，并校验回执的项目/收件人/模式/配额。正向授权缺少收件人即拒绝，业务错误不重试。
7. 授权卡展示服务地址、型号、图像范围和不转授其他服务的说明；管理入口支持随时打开/禁止，服务离线或配置失效时也能禁止。管理授权本身不自动发起任务；从视觉委托流程批准后，项目/单任务授权都带明确 consentId 发起任务。
8. 关闭共享 HTTP 客户端的自动重定向。3xx 作为不可重试的服务错误，不将相同图像/认证自动转发至 Location。实际视觉预留记录增加非秘密 recipientId，费用、范围、图像重编码与未知结果计量规则不变。

## 兼容与边界

- 旧正向授权需要在新界面重新明确授权；旧任务若引用旧或不匹配的授权，不能继续使用，须重新委托。旧数据库不被本轮测试打开或迁移。
- 本轮仅 OpenAI 兼容协议的实际收件人隔离，不等于 Anthropic/Gemini 原生 Adapter 或完整 fallback。旧 provider_fallback 辅助模块的配置/key 判断不构成终用户图像同意。
- 授权控制图像发送；已发送/已进入预留的请求、已收到的观察缓存、审计与备份不能撤回。文本推理范围和作者记忆仍按原有规则；云作者记忆仍禁用。
- 地址/型号身份不等于服务商驻留、条款版本、摄影质量或实际账单证明。不能控制对端内部的数据处理或转发。真实服务与质量门槛保留。
- 同一授权与回执机制复用（DRY/KISS），冻结实例负责收件人核对、consent 负责事务权限（SRP）；不新增通用路由框架或表（YAGNI）。正式照片、作品序列及人工记忆不因授权操作改变。
