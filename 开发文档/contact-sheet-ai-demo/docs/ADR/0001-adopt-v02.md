# ADR 0001：在现有工程上接入 v0.2 GUI × Agent 需求

日期：2026-10-13。状态：需求基线已接入；代码升级待执行。

用户提供新版需求包。采用 `planning-v0.2/docs/DEVELOPMENT-SPEC.md` 为后续产品/架构基线，保留源包与 SHA256；旧 M0 评审、M1 实现和测试记录作为历史，重新按新版门槛评估缺口。

复用当前单 package Tauri/React 工程、npm/Cargo 锁、GUI、图像流水线和数据库数据。不因为示例目录树迁移至 monorepo，不照附件中的新工程模板重新初始化 M0；这是基于用户当前工程状态的实施判断。

新增统一 CommandService，GUI/Agent 都依赖它；后端派生可信 actor/source，Agent 只能写草案，ApplyDraft 仅存在用户批准入口。版本、Undo/Redo、commandId 幂等先落在 M1。旧 M2 AIRun/AISuggestion 计划被 AgentTask/ToolCall/DraftReview 替代。

新包 0001 不能升级当前 0001_local_core，内存库复现 `no such column: sequence_id`。后续使用新增兼容 migration 与备份/升级回归；保留旧 migration、实体 ID 和历史，不重建用户数据库。

§6.3 工具表的阶段标注与总体路线有冲突，选择 §12 的 M2 工具/草案阶段；schema 缺少 actorId/issuedAt、Redo 未单列等差异在工程契约实现时补齐，暂不改写原始下载包。全部观察、工作顺序和验收覆盖见 [V0.2-ADOPTION.md](../V0.2-ADOPTION.md)。

该决定遵循 KISS/YAGNI：保留已有结构和依赖，按当前里程碑实现；遵循 SRP/DIP：IPC/工具适配与事务领域规则分离，使用唯一正式状态。
