# ADR 0037：M3 本地作者记忆的显式授权与任务绑定

日期：2026-10-17。状态：采用，范围为单一本地作者的离线任务；M3 整体仍 partial。

## 问题

已有 0018 设置表和跨项目投影辅助函数，但无 GUI 授权入口，设置直接写 SQL；投影混合不同项目的可编辑假设，而证据列表仍属于当前项目。Agent 的上下文与工具仍仅检索当前项目。直接开放全库 FTS 会纳入未确认、已归档或已共享项目，也无法保证撤权后旧历史不再被执行。

## 决策

1. 增加严格 SetCrossProjectMemory { enabled }，复用 MemoryRequest → CommandHandler → SQLite 写事务和持久化回执。默认关闭，不接受来自调用者的 user/creator 身份；当前桌面仅有 local 单一作者。开启需 GUI 明确确认，关闭直接执行。历史直接设置的 true 必须重新走有效开启审计；重复同值不改变时间或授权 epoch，重复 request_id 返回原回执，冲突拒绝。没有新迁移或依赖。
2. 开启只允许 mock 离线任务读取其他活跃 LOCAL 项目的已确认、有有效支持证据、与目标关键词相关的假设。PROMOTING/SHARED_CACHE 来源和目标、归档项目、未确认/停用/已纠正/已退役假设排除。跨项目相同关键词去重；当前项目或有效来源中的纠正、停用、退役、假设墓碑阻止同词通过另一个来源复活。证据全部失效只排除该来源，不替其他有效来源作永久否决。
3. 检索输出保留 source_project_id、memory_id、evidence_refs 和 counterexample_refs，不携带来源照片路径、照片 ID、原始备注或像素。存储假设仍为 project_local，跨项目只是受限引用视图，不自动把项目判断升级为永久风格。上下文最多 3 条、工具/只读视图最多 10 条，项目内线索优先。工具既有 global_confirmed 枚举与 v2 retrieve_memory 别名使用相同门槛；project_local 仍只读当前项目。
4. 云模型拒绝作者级跨项目检索，也不注入作者上下文。此开关不代表任何供应商传输授权，不改变既有本项目文本/视觉权限。共享项目不继承私人记忆。完整 Creator/Workspace 多身份隔离、供应商专属授权另行实施，不能把当前单机假设当作完成 M02 身份要求。
5. StartTask 把 version=1 的授权及来源摘要写入不可变 author_memory_binding step。摘要包含有效设置、全局授权 epoch、提供方、目标 LOCAL 状态，以及最多 100 个来源的项目 ID/证据高水位/有效记忆命令数；不含证据正文。之后的检查点只复制原绑定，恢复不能刷新授权。无绑定旧任务仅在有效授权关闭且从未有有效授权变更时允许项目内兼容恢复。
6. ContextBuilder、恢复/反馈、模型请求前、模型回复计量后、工具回放/执行前、最终结果提交前重验绑定。变化要求新委托；运行时记录 paused。模型回复期间来源人工证据变化时，先保留已报告用量，再丢弃回复，不执行新工具或生成草案。记忆控制主动暂停当前项目和所有作者记忆消费者；全局开关变更暂停所有正在执行的本地任务。来源归档/Promotion/普通 GUI 证据变化在下一执行门槛检测。
7. 可编辑假设与证据永远只属于当前项目；其他项目假设放在独立只读列表，附来源链接，不能用当前项目 ID 去修改来源。前端校验投影归属。设置变更刷新所有记忆/Agent 查询，查询失败禁用授权控件。

## 边界与取舍

- 有效来源超过 100 个时任务拒绝，Memory Studio 显示原因并仍可关闭授权；不截断后悄悄使用不完整授权依赖。
- 依赖按所有合格本地项目保守绑定，新建项目或无关来源记忆变更也可能要求新委托；暂不建立反向依赖索引。
- 仍是中文二元关键词/FTS5 的证据规则检索，不是作者风格模型或跨项目语义学习。项目内已有低支持假设规则保持兼容。
- 当前进程内和已有任务/工具回执/备份可能保留历史内容。撤权阻止后续执行和新检索，不承诺清除已读历史或安全擦除。
- 摘要依据受信命令通道的审计，不能防同机恶意直接改库；本地作者身份没有多账号安全边界。
- 复用现有命令、回执、检查点与检索机制（DRY），授权模块与内容检索分别负责（SRP），不引入新服务、表或抽象层（KISS/YAGNI）。
