# ADR 0003：v1.0 M0 GUI 与兼容评分

日期：2026-10-13。状态：已实现，等待 UI/UX 评审。

## 范围

复用已有 Tauri/React 与 Rust/SQLite 本地核心，补齐 v1.0 M0。主规格的 M0 验证为 200 张测试照片 → 人工选 25 张 → 离线本地操作 → 完整退出/重启 → 原图 hash 不变。没有实现模型服务、动态 Agent、上下文检索或偏好推断。

## 决定

- Zustand 仅管理选区、锚点、过滤与面板状态；TanStack Query 管理 Repository 快照。选择规则提取为纯函数，网格组件不执行持久化。
- K/X/U 明确设置 keep/reject/undecided；重复设置不会切换状态或追加事件。批量操作先校验全部照片归属，在一个事务中更新投影和追加一个事件。重复状态保持人工序列顺序。
- 评分为人工 0–5 星，0 表示未评分，不从状态或 AI 推断。新增 `0002_manual_rating.sql`，保留原 `0001_local_core.sql` 校验；临时旧库升级测试验证原 ID、备注、顺序、事件、revision 与源 hash 不变。
- Loupe/Compare 共用 PhotoViewport 与 ZoomControls。100% 对应缓存预览的像素尺寸；不能据此声称原图逐像素检查。同步比较共享缩放比例与归一化平移，独立模式分别控制。
- 网格布局变化时重新测量虚拟行高，避免窗口调整后继续使用旧估计。输入、IME、对话框与拖动把手隔离全局快捷键；对话框关闭恢复 DOM 焦点。
- 原生补验使用独立 `studio.betweenframes.m0review` 标识，保留用户原桌面应用与数据库。Review 产物仅用于本机评审；不是正式签名分发包。
- 工程移动后旧 target 中的 Tauri 插件元数据含旧绝对路径；使用 `target-v1` 重建，不删除旧产物，不修改全局 Cargo 配置。

## 权衡与后续

Repository 接口是当前 GUI 写入边界；新增业务 IPC 沿用已有 Store 事务。唯一 CommandHandler、commandId/idempotencyKey、Undo/Redo 与序列版本属于 M1，本轮不伪装成已完成。此范围保持 KISS/YAGNI；共享视图与批量事务避免重复实现（DRY），UI/Repository/Store 职责分离（SRP/DIP）。

用户提供的结构化记忆与分层上下文方案进入 [补充约束](../MEMORY-CONTEXT-ADDENDUM.md)：ContextBuilder 在 M2，Evidence/Hypothesis/FTS5 在 M4。12,000 文本 tokens 是实验建议，尚未作为固定默认。

证据见 [测试报告](../TEST-REPORT.md)、[文件清单](../V1-M0-FILES.md)。本轮停在 M0，评审后才进入 M1。
