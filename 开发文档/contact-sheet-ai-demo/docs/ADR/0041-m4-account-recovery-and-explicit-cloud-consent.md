# ADR 0041 · 账户恢复、持久限流与云模型发送门槛

日期：2026-10-18。范围：v2 M4 身份恢复与 M5 共享回归，不进入 M6/M7。

## 问题

现有数据库执行器只登记 0001/0002，认证已依赖 0006 限流表，导致全新部署注册返回 500。0003–0005 的未登记 SQL 草案使用 UUID 外键，0001 的用户/项目主键却为 text；0007 是带密码占位符的集群管理员模板，不能按普通应用迁移执行。

密码重置默认 scrypt 参数与登录的 scrypt-v1 参数不同。恢复后的密码无法通过登录；输入无上限、兄弟令牌未失效。现有限流固定为一分钟，却被恢复接口称为每小时三次，并在五分钟后清理配额；重发验证依赖并发不安全的 COUNT。

新评论汇总端点仅凭项目管理员身份及环境 Key 就可发送人工评论。项目权限和凭据配置均不是云模型发送同意。

## 决定

1. 不改旧 SQL。显式登记 0001、0002、0006 和新增 0008；0008 使用兼容的 text 外键建立账户/任务结构。0003–0005 保留为未登记草案，0007 保留为未执行管理员模板。服务正常启动仍只查版本/SHA；任何未知登记拒绝运行。生产如有手工建表/迁移记录，必须先审计后制定独立升级方案，不能套用本次临时库结果。
2. 提取 password 模块统一注册、登录、恢复参数。AccountRecoveryService 独立承担恢复/验证，不继续扩大 CloudService。通过可注入邮件交付接口完成不外发的真实 PostgreSQL/HTTP 回归。
3. 用数据库时钟划分分钟、十分钟、小时等固定窗口，各窗口配额独立，原子 UPSERT 并饱和计数。清理保留两天，最长支持一天窗口；批量检查不声称跨 key 单事务。
4. 恢复先锁用户，再重验令牌；成功后所有未用恢复令牌及旧会话失效。验证令牌同样一次性、锁用户、作废同用户其余验证令牌。邮件失败回滚令牌；重发接口明确报不可用，找回接口维持账户存在/不存在的一致受理响应。没有完整时间侧信道等价承诺。
5. Web 提供四语找回、重置、验证与重发入口。新链接使用 `/shared#reset-password=...` / `#verify-email=...`，不自动消费，打开后移出 URL，仅在组件内存保留；兼容原路径查询链接。刷新后需重新打开邮件。旧查询链接的历史服务器日志不能由本次改动擦除。返回按钮明确退出恢复；清理地址的事件不丢失内存令牌。
6. 云评论汇总在实际网络调用前返回 `MODEL_CONSENT_REQUIRED`。专属模型发送授权、预算/撤权、来源和可恢复 Worker/队列接通前，不把现有同步辅助函数称为已完成云 Worker。不修改本地 Agent 能力或草案/正式权威隔离。

## 验证与限制

见 [测试报告](../V2-M4-ACCOUNT-RECOVERY-TEST-REPORT.md)。只在新建隔离临时 PostgreSQL 中执行迁移/账户修改；邮件使用注入交付器，模型 Key 和邮件 Key 显式清空。没有生产 DDL、发送真实邮件、调用模型、用户库升级或提交推送。真实邮件交付、TLS/域名、生产角色/备份和多实例容量仍待验收。
