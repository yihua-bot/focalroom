# ADR 0026：回执存储去平方化（由 ADR 0028 修订）

日期：2026-10-15。当前语义以 [ADR 0028](0028-m1-review-fixes.md) 为准；原方案“重放返回当前项目”的实现已修复。

## 问题与保留的设计

每个 command_events.result_json 都嵌套完整 project.events，会重复保存此前全部历史，导致随命令数平方增长。事件本体已有 append-only 的 decision_events 表，应复用它，继续保存首次命令的业务快照及正式回执字段。

修订后的编码将 project.events 置空，仅在内部持久化 JSON 增加 eventCursor。重放按项目和截止游标补齐当时历史，原始标题、决策、序列、版本和 revision 保持不变。旧完整回执原样返回，原无游标瘦回执根据正式 revision 恢复事件截止位置。详见 ADR 0028 的兼容边界与回归。

原“events 为空则用 snapshot_tx 重建整个当前项目”会返回旧 revision 搭配新业务状态，违反既有幂等语义；已撤回该做法及只核对核心字段的弱化测试。

## 测量纠正

原记录中的“7.99GB→63.7MB / 500 命令”、2→28 命令每秒和每百命令增长数值基于错误的调用次数/存储口径，撤回作为当前验收数据。未保留可核验原始输出，不据此发布缩减倍数。

实际循环是 125×2×5=1250 条 GUI 命令。当前基准逐次累计成功调用并核对持久化回执增量，逻辑数据库大小使用 page_count×page_size，main/WAL/SHM 单独记录。最终复测：1250 次 / 1250 回执增量，15.63 秒，逻辑数据库从 606,208 增至 64,733,184 字节（61.73MiB）；每百命令逻辑增长 5,130,158.08 字节。

这些是 40 张生成图的后端基准，不是原生/低端设备或真实高像素图库达标声明。原始 JSON 与日志见 [修复验收报告](../V2-M1-REVIEW-FIXES-TEST-REPORT.md)。

## 边界

不删除历史、不改旧迁移、不重写既有回执；旧库中的巨型回执保持可读。新编码仍保存完整业务快照，很多照片或版本下的线性增长与事件按需读取留后续实测。M1 继续 partial。
