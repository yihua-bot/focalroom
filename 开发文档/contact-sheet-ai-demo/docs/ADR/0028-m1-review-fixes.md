# ADR 0028：M1 评审修复——有界 RAW 检视与历史回执

日期：2026-10-15。对应 [接续评审](../V2-M1-CONTINUATION-REVIEW.md) 的 R1–R3。本决策修订 ADR 0026 中“重放返回当前投影”的语义及 RAW 检视的来源声明；不新增迁移或依赖，不进入新 M2。

## 有界 RAW 检视

移除检视路径里的 `sips -s format jpeg` 和全局临时检视缓存。该调用不能保证只提取相机嵌入 JPEG，输出也没有尺寸约束。RAW 检视复用导入时已经生成的最长边 1400px JPEG，每次授权前重新检查文件类型、大小（16MiB）和尺寸，失败明确报错。原文件的大小约束先于流式 SHA-256 检查；原图始终只读。

返回 `kind=derived_preview`，客户端显示“RAW 派生预览 · 非全分辨率”，不声明是嵌入 JPEG 或原图。桌面缩放入口统一称“100% 像素”，实际来源在画面中标明；Retina 比例针对当前显示源的图像像素。JPEG/PNG/TIFF/HEIC 的原图直通路径和 64MiB / 3200 万像素边界保留。真正的 RAW 全分辨率/嵌入预览能力仍未交付。

这复用已有缓存和共同 viewport，避免引入额外解码框架与不必要的转换；AI 上传授权和 1400px 视觉通道未扩大。旧全局临时检视文件不由本次修复删除，也不再读取。

## 历史回执保持首次结果

CommandHandler 继续将回执的完整业务快照持久化，但不重复写入其中的事件数组。保存时在 `result_json` 中增加内部字段 `eventCursor`，值为同一事务中该项目 `decision_events` 的最大 rowid。正式状态、事件和瘦回执仍原子提交。

重放时：

1. 新瘦回执按项目与游标查询当时的事件，补回已存业务快照；不调用当前 `snapshot_tx` 来替换标题、照片、序列、版本或 revision。
2. 旧完整回执原样返回。
3. ADR 0026 已写入的无游标瘦回执，根据事件中的正式 revision 找到历史截止位置，再补回当时事件。业务字段仍使用原持久化快照。

事件表已有 append-only 约束，查询同时按项目限制，排序沿用 `created_at DESC,rowid DESC`。新格式用游标避免依赖时间戳精度。普通项目快照与回执补全复用同一事件查询函数（DRY）。不重写旧回执行，不修改数据库结构，不停用审计触发器。

恢复回归：完整回执在后续编辑、命令别名重放和数据库重开后逐字段相等；旧完整/旧瘦格式兼容；无操作回执保持首次历史和 revision；新持久化回执的事件数组仍为空。

## 性能基准与证据

增长基准实际执行 `125×2×(1+2×2)=1250` 条 GUI 命令。每次成功后累计次数，并与 `command_events` 行数增量核对；所有吞吐/每百命令增长按实际次数计算。

逻辑数据库占用使用 `PRAGMA page_count × page_size`，包括已提交但可能仍位于 WAL 的页面；另外记录关闭连接前的 main/WAL/SHM 文件大小。性能输出为可解析 JSON。原来的“7.99GB→63.7MB / 500 命令”和归一化数字撤回，新的结果只引用本次保存的原始输出，不重跑有缺陷版本制造对照。

真实 HEIC/CR2 样本测试改为显式 ignored，再在具备样本时单独执行；缺样本不能直接 return success。16 位 PNG 与 ICC 字节保留拆成独立断言，ICC JPEG 的 APP2 长度包括两个序号字节；这些测试不宣称显示器色彩准确。
