# AI 跨端统一：以桌面实现为准

更新：2026-11-02。iPhone 产品入口已接入桌面同一份 Rust AI 核心；当前代码尚未签名发行，真实模型质量与真机体验未验收。

## 共用范围

以桌面 1.4.9 的实际入口为基准：聊天使用 AgentEngine 的纯文字聊天路径；选片任务使用 StartConversation、ContextBuilder、PolicyGate、工具循环、草案与持久回执。iPhone 的普通 AI 入口已退出原先单独组装 Responses 请求的实现。

- 提示词共用 prompts/focal-chat-v2.md 与 prompts/focal-agent-v2.md。跟随用户语言，中文输入默认自然中文，只保留必要英文名称和标识；两端不再分别维护语言规则。
- 聊天共用请求正文、输入校验和托管账户策略。手机持久化原请求编号，未确认结果按原编号查询，重启不盲目重发。
- 任务共用规划、工具权限、预算、图片授权、追问、暂停/恢复/取消、观察记录、草案与偏好审阅；适配层不另写任务循环。
- 语义检索共用 Apple NaturalLanguage 原生桥接；系统资源实际可用性仍需真机验收。

同一核心不意味着设备间自动同步聊天和执行库。手机聊天当前显示完整回执，不提供桌面新增的逐字流式展示；旧无项目归属消息作为只读历史保留，不伪造任务或视觉证据。

## 原生接入与资料边界

src-tauri 的 native-agent feature 关闭桌面窗口与插件装配，编译成静态库，经 native/focalroom_agent.h 的 C ABI 提供 JSON 调用。NativeAIClient 在后台执行，Xcode 构建阶段调用 scripts/build-agent-core.sh 链接同一份核心。正常桌面构建仍使用默认 desktop feature。

会话打开时复用 CloudAuth 核验，令牌只驻留 Rust 内存；执行资料按服务和账户隔离。SQLite 为手机独立执行资料，不替代本机项目 JSON 或云端权威数据。账户、项目切换与迟到回执保持身份隔离。ABI 输入上限 16 MiB，主要承载元数据；错误保留结构化错误码并以中文展示。

native_agent/context.rs 将当前来源映射到既有核心项目、照片与序列模型，不新增数据库迁移。本机与云端身份分离；全量元数据最多 10,000 张，单任务范围沿用核心上限，不能将部分镜像冒充完整项目。源版本变化使旧草案失效；任务执行中不改写其上下文。未授权照片不提供预览，元数据不冒充实际观察。

图片由用户逐次确认后提供，最多 4 张，核心按最长边 512 像素 JPEG 发送，去除位置等私密元数据；不发送原片、不隐式创建云端项目。取消或切换来源会撤销未消费授权。

## 草案审阅与正式写入

- 本机选片：显示实际草案项目，用户逐项确认后原子写入选片状态及序列；核对来源版本，保留原片摘要，以草案版本和所选项形成幂等回执。重启后可读取已采纳状态。
- 云端选片：冻结已有 proposal.create / proposal.submit 命令与基线；重试沿用原命令，进入现有提案审阅。核心镜像不直接修改云端正式数据。
- 本机画布：重新核对草案画布版本和节点；支持的照片、文字节点经明确确认后追加到本机画布，保留一次批量撤销。复杂、旋转或不支持节点仅预览。已有画布摘要最多 100 个节点，不能视为整幅画布的无损编辑模型。
- 云端或冻结来源：收紧画布写权限，恢复/重放不能扩大已经冻结的授权。当前不支持将 AI 画布草案发布到云端。
- 偏好建议：用户确认后调用同一套审计命令保存项目偏好，不自动存入。

手机采用适合窄屏的段落、标题和列表，显示中文任务状态、观察事实、推断与不确定性；草案在独立审阅页核对，成功回执在页内显示，避免弹层关闭时丢失反馈。

## 构建与验证

脚本支持 aarch64-apple-ios、aarch64-apple-ios-sim、x86_64-apple-ios，使用 rustup 对应编译器，不自动安装组件或修改全局设置；缺少目标标准库时可使用 DerivedData/NativeAgent/sysroot 下与编译器匹配的项目本地标准库。本轮模拟器标准库取自 Rust 官方分发并核验 SHA256。

本轮最终结果：

- Rust 原生核心库：177 通过，2 个依赖 Apple 系统模型资源的测试显式忽略；包含 600 张照片完整上下文、C ABI 到真实工具循环、关闭重开无重复请求、只读画布授权重放。
- 原生核心严格 Clippy、Rust 格式、默认桌面库编译、contracts:check、git diff --check 通过。
- Swift XCTest：74 项，10 项集成测试显式跳过，0 失败；另有 3 项 Swift Testing 账户测试通过。覆盖部分采纳、版本冲突、原片保护、账户隔离、冻结提案重试、画布幂等及撤销。
- iOS 设备目标和模拟器 Debug 构建通过；设备目标使用 CODE_SIGNING_ALLOWED=NO，不代表签名安装或分发完成。
- 专项模拟器界面测试通过：中文聊天排版 → 图片授权取消/重新确认 → 实际观察 → 选片草案部分采纳 → 重启保留。测试使用生成图片、临时 PostgreSQL/Nest 服务和确定性上游，5 次模型桩请求，真实模型调用 0 次。核对了审阅前原资料未变、只采纳勾选项、原片摘要不变、无隐式云项目、取消与重启不多发请求。

专项证据：test-results/ai-unification-focalroom-pg-tests-WmkTjX/，含 result.json、requests.json、SharedAI.xcresult 与中文界面截图。运行入口为 node apps/api/test/run.mjs apps/mobile-ios/scripts/verify-ai-unification.mjs；需独立评审模拟器。早期测试暴露并修正了测试容器定位与采纳成功弹层反馈问题；上述为修正后的最终通过结果，不能推称整个旧 iOS UI 套件均已通过。
