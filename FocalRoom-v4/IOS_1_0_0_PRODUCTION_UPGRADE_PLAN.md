## 升级步骤

1. **冻结并构建**：在固定源码快照下构建与生产架构匹配的 API/Web 镜像，记录镜像 digest、构建输入摘要和测试结果。构建上下文排除密钥、私有配置、iOS 归档/IPA、描述文件及测试产物；不把这些文件传入 Docker。
2. **备份并验证恢复**：选择短维护窗口，暂停会改变数据的 API/Worker，取得 PostgreSQL custom dump、预览/对象介质清单与所需私有有效配置的受限备份；校验摘要，在隔离环境实际恢复并核对结构和关键计数。备份与密钥不进仓库。
3. **受限迁移**：使用一次性 migrator 配置执行已核对的迁移集合；常驻 API 继续使用最小权限应用角色，不保留迁移凭据。逐份复核迁移登记摘要和新表/约束/审计触发器。
4. **切换固定镜像**：基于盘点得到的当前有效 Compose 配置，只替换本项目 API/Web 镜像。历史报告中的 `/opt/focalroom/releases/hosted-ai-20261019/runtime.compose.private.json` 仅作为查找线索，不能未经核对直接使用旧配置；禁止只启动仓库默认 Compose 覆盖邮件、AI 或其他生产设置。
5. **上线只读检查**：健康、未登录鉴权、登录/刷新、设备/事件/回执、私有项目权限、媒体授权及旧桌面/Web 兼容检查。分别记录路由存在、功能集成、真实模型质量，不能互相代替。
6. **AI 单独验收**：用户已选择稍后进行真实调用。本次不自动启用新模型策略、赠送额度、重跑 UNKNOWN 请求或开启队列/Worker。后续使用指定的已验证测试账号，先确认实际账户策略与可用额度，展示素材和费用上限，再执行一条明确授权的真实请求。

## 回退与停止条件

- 保留原 PostgreSQL 容器、卷、对象、旧镜像和受限备份，不执行 down/prune 或删迁移登记。
- 新增迁移后旧程序可能因严格版本清单拒绝启动。应用回退必须使用兼容新结构的镜像；不能承诺直接回到旧镜像就能恢复。
- 备份覆盖恢复会丢失备份后的写入，必须另行确认停写窗口和数据影响，不能自动执行。
- 恢复环境中的 AI 排队/未知请求按既有 quarantine 流程处理，不将备份任务恢复为可以重新外发的授权。
- 任何备份/恢复、迁移摘要、权限或健康检查不符即停止切换；保留现场，不通过放宽断言掩盖问题。
